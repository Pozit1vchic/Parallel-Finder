Parallel Finder помогает искать монтажные параллели: моменты, в которых персонаж повторяет движение или принимает похожую позу. Видео обрабатывается локально. Найденные пары — **кандидаты для просмотра**, а не автоматически подтверждённые совпадения.

> Текущая версия — **0.1.0-rc.19.2**: подписанные обновления из GitHub Releases, Stable/Beta, собственный QML-диалог и отдельный updater с откатом. Установка выполняется только по согласию пользователя. Архитектура, выпуск подписанных пакетов и ограничения — в [описании обновлений](docs/updates.md); ускорение матчера, группы результатов и исправления интерфейса — в [изменениях rc18](docs/rc18-release-notes.md). Сборки находятся в `release`; публикация GitHub Release выполняется отдельно.

## Установка

Интерфейс сохраняет привычную компоновку, но откликается на действия: связанные метки A/B, короткое проявление новых кадров, ограниченное появление первых карточек, плавное раскрытие настроек, переключение галочек и выпадающих списков. Анимации длятся 120–220 мс, не требуют дополнительных blur/shader-эффектов и не работают бесконечно в простое. **Настройки → Оформление → «Отключить анимации интерфейса»** убирает эти переходы; видео при этом продолжает воспроизводиться как обычно.

Сборки публикуются в [GitHub Releases](https://github.com/Pozit1vchic/Parallel-Finder/releases). Выбирайте файлы приложения, не архивы исходников GitHub.

| Вариант | Как запустить |
|---|---|
| **Portable ZIP** | Распакуйте **весь** архив в отдельную доступную для записи папку. Запустите `ParallelFinder.exe`. Не запускайте EXE внутри ZIP и не переносите его отдельно от DLL. |
| **Setup EXE** | Запустите установщик и выберите папку. Он добавляет приложение в меню «Пуск» и предоставляет удаление. |

Windows x64. Python, Visual Studio и CUDA Toolkit для обычного запуска не нужны. Portable означает запуск без установщика; настройки и загруженные модели могут сохраняться в пользовательской папке AppData. Точный путь к кэшу отображается в настройках.

Неподписанная сборка может вызвать предупреждение SmartScreen. Проверяйте источник и SHA-256 из релиза; отключать защиту Windows не требуется. Модели и дополнительные ускорители могут распространяться отдельно.

## Первый запуск

Окно появляется до завершения проверки ускорителя. Пока плашка показывает проверку провайдера, можно добавить видео и настроить поиск; запуск анализа станет доступен после проверки. Плееры A/B создаются только при выборе результата.

1. **Добавьте видео** кнопкой, перетаскиванием или выберите папку. Плашки добавленных файлов появляются прямо в области загрузки, над кнопками «Очистить / Удалить»; выберите плашку, чтобы удалить конкретный источник.
2. В левой панели раскройте **«Дополнительные настройки»**. По умолчанию выбрана **YOLO26 · medium**; далее приложение восстанавливает последнюю выбранную модель. `✓` означает, что файл найден, `↓` — что его нужно скачать. Выбор отсутствующей модели автоматически запускает загрузку; дождитесь её завершения.
3. Для первого прохода выберите **«Баланс»** и **«Гибрид (движение + кадры)»**. Если нужны только повторяющиеся жесты, выберите **«Движение»**.
4. Нажмите **«Запустить анализ»**. Первый проход может быть заметно дольше повторного: приложение сохраняет промежуточные результаты в кэш.
5. Выберите пару справа. **↑ / ↓** переключают результаты без перехода с конца на начало; плавающая **«↑ Вверх»** возвращает к первой паре. Галочка выбирает пару для экспорта, а **«Сортировать по»** меняет порядок по сходству, сцене или времени.
6. У **каждой пары**, включая статичную позу и положение головы, можно запустить видео внутри панелей A/B. Кнопка под A управляет A, кнопка под B — B, общая **«Воспроизвести A/B»** запускает обе стороны. Повторное нажатие ставит воспроизведение на паузу; смена пары его останавливает. Отдельной кнопки «Повтор» нет. Статичное превью показывает до 4 секунд от найденного момента, в пределах сцены; движение — найденный отрезок.

Видео не отправляется на сервер. Интернет требуется для скачивания отсутствующих моделей и пакетов ускорения.

В настройках оформления список предлагает только установленные поддерживаемые шрифты. Inter и Montserrat не скачиваются автоматически: установите нужный шрифт в Windows или выберите свой `.ttf`/`.otf` через добавление шрифта. Если файл был перемещён или удалён, приложение покажет ошибку загрузки; выберите его заново. «Сбросить оформление» возвращает цвет, шрифт, прозрачность и анимации к значениям по умолчанию, не меняя язык и параметры анализа.

## Какую модель выбрать

Нужна **pose-модель в формате ONNX**. Обычная модель детекции объектов или исходный файл `.pt` не заменяют pose-экспорт.

| Размер | Когда выбирать | Компромисс |
|---|---|---|
| **n / nano** | Первичная проверка, слабый компьютер | Быстрее, но мелкие и перекрытые суставы могут определяться хуже |
| **s / small** | Повседневный поиск при ограниченных ресурсах | Умеренная нагрузка |
| **m / medium** | Начальная точка для проверки качества | Больше вычислений; не гарантирует больше правильных пар |
| **l / large**, **x / xlarge** | Сложные кадры и запас памяти GPU | Медленнее и требовательнее; улучшение проверяйте на своём видео |

В каталоге есть варианты YOLOv8, YOLO11 и YOLO26. Размер модели и поколение — разные параметры: самая новая или самая большая модель не обязательно лучше для конкретного сценпака.

Для начала используйте **YOLO26m-pose**: эта модель включена в текущий комплект приложения и использовалась в контрольных прогонах Soldier и Dean. Последний выбор сохраняется отдельно от пути к файлу. Установленная модель не загружается повторно; если выбранного файла нет, анализ блокируется до успешной загрузки. Возобновить неудавшуюся загрузку можно повторным выбором модели.

Выбор отсутствующей модели запускает загрузку только при наличии опубликованного `manifest.json` и соответствующего файла. Размер и SHA-256 проверяются до установки. Если приложение сообщает, что манифест недоступен, модель ещё не опубликована либо загрузке мешает сеть — повторный анализ это не исправит.

Модели хранятся в `%LocalAppData%\ParallelFinder\ParallelFinder\models`. Подготовка файлов, точный тег релиза и инструкция публикации — в [руководстве по моделям](docs/models.md).

**Режим точности** меняет параметры отбора совпадений. **Обработка кадров** меняет частоту анализа. Это не выбор разрешения исходного видео: рабочие кадры для vision-анализа ограничены 720p; оригинал остаётся неизменным.

Короткая поза должна наблюдаться минимум в трёх независимых кадрах на протяжении 0,3 секунды. Если руки уверенно видны только внутри части отрезка, поиск отдельно проверяет этот непрерывный участок; одиночный удачный кадр и скрытые суставы не заменяют доказательства. Для подтверждённой позы конечностей «Быстрый поиск» допускает больше различий ракурса, чем «Высокая точность»; проверка того же персонажа остаётся обязательной. Повышение качества обработки кадров даёт больше наблюдений, но не гарантирует больше результатов.

### Проверка персонажа

Поиск рассчитан на **одного и того же человека или персонажа**: похожий жест другого человека сам по себе не считается подходящей параллелью. Проверка лица и внешнего вида тела остаётся частью обычного анализа; уверенное несогласие лиц запрещает совпадение. Режим «Костюм / маска» и его специальная ветка сравнения удалены в RC.13; старое поле настройки игнорируется и не влияет на новый анализ.

Закрытое или маленькое лицо, перекрытия и одинаковая одежда у разных людей снижают надёжность проверки личности. Это ограничения обычного анализа, а не отдельный режим, который можно включить.

## Режимы поиска

| Режим | Что сравнивает |
|---|---|
| **Движение** | Изменение позы во времени |
| **Статические кадры** | Похожие видимые позы, без требования повторения движения |
| **Гибрид (движение + кадры)** | Кандидаты обоих типов |

Для крупных планов результат может быть помечен **«Похожее положение головы»**: это не сравнение всего тела. Сходство лица используется как дополнительный признак, а не как доказательство повторения движения.

Чтобы один клип не повторялся в большинстве карточек, один исходный монтажный отрезок участвует не более чем в одной паре **суммарно** для поз и движения. Пары с наблюдаемым телом или движением получают приоритет перед совпадениями одной головы; допустимые перестановки пар помогают задействовать больше разных шотов. Для портретов проверяется также расположение деталей исходного кадра: возвращение к тому же ракурсу в другой склейке не создаёт новую индивидуальную параллель. Подтверждённые позы тела и движение сохраняются перед этим ограничением. Счётчик результатов не является оценкой качества: отсутствие повторов не доказывает, что найдены все полезные параллели. [Актуальная проверка RC16.3](docs/rc16-repeat-search-2026-10-05.md).

**«Повторный поиск»** под выбором состава анализа включает более широкий поиск: больше кандидатов из разных шотов и дополнительные короткие отрезки с уверенно видимыми конечностями. Пороги оценки не снижаются, модель не заменяется и кадры не придумываются. При пригодном кэше YOLO повторно не запускается; при отсутствии кэша сначала выполняется обычный анализ. Этот режим работает дольше и не гарантирует новых результатов на каждом видео. Для гарантированного повторного извлечения признаков используйте очистку кэша в настройках.

## Экспорт

Отметьте пары и нажмите **«Экспорт»**.

- **JSON / CSV / TXT** — таймкоды, источники и данные для дальнейшей обработки.
- **FFMPEG** — отдельные MP4-файлы A и B, от начала найденного совпадения до конца его сцены. Разрешение и частота кадров исходника сохраняются; ограничения длиной 25 секунд нет.
- **Точно** — точное начало с перекодированием. Конец обнаруженного жёсткого перехода дополнительно уточняется по исходным кадрам, чтобы соседний шот не попадал в клип; пропущенный детектором переход эта проверка не восстанавливает. Приложение сначала перематывает к нужному месту, а не декодирует весь исходник с начала для каждого клипа. При доступном аппаратном H.264-кодировщике используется он; иначе — программный x264 с ограниченным числом потоков.
- **Быстро** — копирование потока; границы зависят от ключевых кадров.
- **Как в видео** — порядок по источнику и времени. **По сортировке** — порядок результатов.
- **Совместить все клипы по возрастанию таймкодов** — один `<префикс>combined.mp4` из выбранных отрезков A/B. Сначала меньший таймкод; при равных таймкодах — имя источника. Точные дубликаты одного диапазона одного файла исключаются; частично перекрывающиеся диапазоны остаются отдельными клипами. Все отрезки перекодируются в размер и FPS первого клипа с сохранением пропорций, звук приводится к stereo/48 kHz; для исходников без звука добавляется тишина. Выбор «Быстро» в этом режиме недоступен.

Укажите папку и префикс имени. MP4-экспорт выполняется в фоне; рядом с числом готовых файлов отображается процент текущего клипа. **«Отменить экспорт»** останавливает текущую нарезку и оставляет уже готовые файлы. Незавершённый временный файл удаляется. Для объединённого MP4 промежуточная папка удаляется и при отмене; итоговый файл заменяется только после успешной сборки, поэтому старый итог сохраняется при ошибке. Если кодировщик две минуты не сообщает продвижения, он автоматически останавливается с ошибкой; сама программа не закрывается. Длинная нарезка с продолжающимся прогрессом не прерывается по общему лимиту времени.

CUDA/TensorRT ускоряют анализ, но не заменяют видеокодировщик FFmpeg: высокая скорость анализа сама по себе не означает аппаратный MP4-экспорт. Программное кодирование продолжает использовать CPU, хотя число потоков ограничено.

EDL, FCPXML и After Effects JSX реализованы в библиотеке экспортёров, но пока не доступны в текущем диалоге приложения.

## CPU, DirectML, CUDA и TensorRT

Для владельца проекта: [подготовка пакетов и публикация для кнопки скачивания](docs/provider-packages-howto.md). Большой TensorRT-пакет может скачиваться частями; для этого требуется обновлённая сборка приложения с поддержкой `parts`.

| Режим | Оборудование и условия |
|---|---|
| **CPU** | Работает без GPU-ускорителя; может быть медленным |
| **DirectML** | Совместимая видеокарта AMD, Intel или NVIDIA и DirectML runtime |
| **CUDA** | NVIDIA, совместимый драйвер, ONNX Runtime CUDA и согласованные зависимости |
| **TensorRT** | Поддерживаемая NVIDIA и совместимые TensorRT/CUDA/ONNX Runtime; первая подготовка модели может занять время |
| **Auto** | Выбор из доступных провайдеров |

**DirectML:** откройте Настройки → Анализ, выберите DirectML и нажмите **«Скачать компоненты»**. Приложение загрузит около 215 МБ из официального NuGet Microsoft, проверит SHA-256 и установит Windows x64 DLL в AppData. После установки закройте и снова откройте приложение. Нужны совместимые видеокарта DirectX 12 и драйвер.

**CUDA / TensorRT:** выберите провайдер в Настройки → Анализ и нажмите **«Скачать компоненты»**. Приложение читает каталог из отдельного релиза `runtime-v1`, проверяет размеры и SHA-256, устанавливает пакет в `%LocalAppData%\ParallelFinder\ParallelFinder\providers`. CUDA-пакет занимает около **1,65 ГБ**, TensorRT — **3,30 ГБ** и загружается двумя частями. После установки полностью закройте и снова откройте приложение. Драйвер NVIDIA устанавливается отдельно; наличие пакета ещё не означает совместимость с конкретной видеокартой.

Каталоги `v0.1.0-models/manifest.json` и `runtime-v1/providers.json` доступны на момент аудита 30 сентября 2026. В первом перечислены 15 pose-моделей, во втором — CUDA, TensorRT и DirectML. Это проверка каталогов, а не результат полного скачивания гигабайтных пакетов на чистой машине. Для ручной установки используйте полный согласованный набор DLL: **[инструкция и структура папок](docs/GPU-SETUP.md)**.

Настройки анализа и оформления сохраняются в `%LOCALAPPDATA%\ParallelFinder\ParallelFinder\settings.json`. Portable и установленная версия используют общий профиль. Если файла нет, язык по умолчанию — English.

Превью создаются в отдельной временной папке текущего сеанса и удаляются при нормальном закрытии. При следующем анализе убираются оставшиеся после аварии собственные сеансы старше суток; активный второй экземпляр защищён блокировкой. Пользовательские видео, модели, провайдеры и полезный кэш анализа эта очистка не удаляет.

CUDA/TensorRT не являются универсальной гарантией ускорения всего анализа: декодирование, поиск кандидатов и подготовка данных тоже занимают время. Сравнивайте один ролик, одну модель и одинаковые настройки; не сравнивайте холодный запуск с проходом из кэша.

### Большие видео и 4K

В RC.13 полный кэш хранит позы, признаки личности, контекст и число сцен. Повторный проход с тем же видео, моделью, провайдером, качеством и режимом пропускает декодирование и inference, но заново проверяет и сортирует пары по текущим настройкам. Старый кэш обновляется за один проход; смена параметров, влияющих на признаки, требует нового анализа. На контрольном 27-минутном Moshenniki: **41,377 → 6,522 с**, те же **44 пары** и оценки. В первом из этих повторных проходов позы **уже были в кэше**, но видео ещё декодировалось: 41,377 с не является временем анализа с нуля. Это ускорение **повторного прохода**, не обещание обработать незнакомое длинное видео за шесть секунд; [методика RC.13](docs/rc13-ui-performance-export.md).

В текущем дополнении к RC.14 ускорен и **первый анализ**: декодер готовит следующие выбранные кадры параллельно работе моделей, с очередью максимум из трёх кадров. Матчер переиспользует точные расстояния и identity-evidence, не меняя порядок кандидатов и правила отбора; подготовка входа YOLO повторно использует буфер и точные карты координат. Модель, частота анализа и пороги качества сохранены. На Dean / Soldier / Peter с новым пустым кэшем, включая превью, измерено **13,218 → 9,286 / 48,851 → 34,793 / 59,073 → 43,559 с**; Moshenniki, 27:19 — **259,055 → 187,061 с**. После второго этапа отдельно измерено ускорение его матчера **34,995 → 17,739 с**. Все поля результатов CUDA совпали, кроме временных путей PNG. Это результаты одного ПК, не обещание для любой конфигурации; [методика и ограничения](docs/cold-analysis-performance.md). Ранее собранные архивы автоматически этим изменением не обновляются.

**Второй performance-аудит** заново проверил уже ускоренную сборку. Убрана лишняя копия рабочего кадра batch 1; проверка кеша PNG и сохранение новых превью перекрываются с ограниченным числом потоков/буферов. Дополнительно измерено сокращение времени первого анализа CUDA на **8,7–12,6%**, повторного — на **15,2–41,8%**; TensorRT с готовыми движками — на **5,3–14,9%** и **22,0–41,5%** соответственно. Проверены все четыре материала: пары, оценки, таймкоды и байты кеша не изменились внутри каждого backend. Реальное выполнение CUDA/TRT и переиспользование движков подтверждены профилями, не только индикатором. Это дополнительный выигрыш относительно предыдущего прохода, не сумма процентов и не снижение качества; [полный отчёт и границы замера](docs/second-performance-audit.md).

Исправлена передача сложных параметров CUDA/TensorRT и постоянного пути TensorRT engine/timing cache. Первая подготовка движка может быть долгой; наличие кэша не отменяет её. Исправленная TensorRT FP16-конфигурация не объявляется численно равной CUDA: при переходе на неё требуется обновить наблюдения одним новым проходом, а Auto учитывает реально выбранный провайдер.


В RC.9 CPU-декодирование использует несколько потоков — автоматически до восьми, с учётом числа логических процессоров; явно выбранное число потоков тоже ограничивается восемью для декодера. При CUDA/TensorRT, включая Auto с NVIDIA-провайдером, для источников **больше 1920×1080 по числу пикселей** приложение пробует аппаратное декодирование **NVDEC**. Его задача — быстро прочитать сжатое видео; модели по-прежнему получают рабочие кадры не больше 1280×720.

В память CPU передаются только кадры, выбранные для анализа, а не каждый видеокадр. Способ уменьшения сохранён: экспериментальное уменьшение прямо на GPU изменяло контрольные пары, поэтому в обычном приложении оно **не включено**. Для 1080p и меньших источников используется многопоточный CPU-декодер. Неподдерживаемый кодек, недоступный GPU, поворот, анаморфный формат или непроверенный цветовой формат также включают CPU-путь автоматически; исходник не изменяется и отдельный proxy-файл не создаётся.

Для NVDEC нужны поддерживаемая NVIDIA и драйвер; это отдельная часть обработки, не новая модель и не ещё один скачиваемый пакет. В поставляемом FFmpeg есть CUVID-декодеры H.264/HEVC/AV1/VP9, но аппаратная поддержка зависит от конкретного GPU и формата видео. Анализ всё ещё включает pose, лицо/ReID, поиск и создание превью — сокращение времени чтения видео не означает такого же ускорения всех этапов. [Измерения, ограничения и воспроизведение тестов](docs/video-decode-performance-2026-09-30.md).

[Подготовка пакетов NVIDIA для разработчика](docs/runtime-distribution.md).

В **RC19** NVIDIA-путь также поддерживает проверенный 10-битный HEVC: перед уменьшением кадра восстанавливается точное планарное представление CPU-декодера. Поиск кандидатов и выбор личности распараллелены; повторные проверки лиц внутри одного анализа используют прежние расчёты матчера, но заново применяют ограничения личности и отбор уникальных пар. Временный кеш ограничен доступной памятью и живёт только до конца анализа. Кнопка повторного анализа по-прежнему сбрасывает кеш выбранных видео. [Проверки RC19 и ограничения качества](docs/rc19-validation.md).

В **RC19.1** дорогая проверка возвращающихся ракурсов выполняется для перспективных пар после быстрых ограничений; точные сравнения миниатюр сцен используют ограниченный кеш, а альтернативы занимают меньше памяти. Пороги и проверка исходных кадров сохранены; условия замеров и ограничения — в [проверке rc19.1](docs/rc19.1-validation.md).

В **RC19.2** GPU-распознавание поз перекрывается с обработкой лиц, ReID и трекингом предыдущих кадров. Очередь ограничена памятью и сохраняет порядок кадров; CPU-путь и настройка одного потока остаются последовательными. Подготовка кандидатов матчера распараллелена, сравнения распределяются небольшими блоками между свободными потоками; автоматический режим использует доступные логические процессоры, до 256. Модель, частота выборки, пороги и правила отбора не изменены. [Измерения и ограничения RC19.2](docs/rc19.2-validation.md).

## Честно о результатах

- Интерфейс показывает **сходство движения, позы или положения головы**, а также **сходство сцены**. Эти проценты — оценки алгоритма, а не вероятность правильного совпадения: 90% сходства не означает 90% точности. Высокое сходство фона само по себе не подтверждает параллель.
- Маленькое лицо, маска, перекрытия, монтажные склейки и похожая одежда затрудняют поиск.
- Соседние похожие кадры одной локации подавляются эвристикой; возможны как пропуски, так и ложные совпадения.
- На контрольной YOLO26m сохранены **3 из 3** пользовательских пар на Soldier и **3 из 3** на Dean; на Dean дополнительно проверена поза с прицеливанием около **2,7 / 6,3 с**. Отмеченные ложные пары исключены (5 на Soldier и 4 на Dean, включая «скрещённые руки / пистолет»). На YOLO11n для Dean результат хуже. Эти небольшие выборки не измеряют точность на всех видео; [методика RC.11](docs/matcher-supported-poses-2026-09-30.md).
- Проверка на разных NVIDIA GPU, длительные стресс-тесты и полный лицензионный аудит дистрибутива ещё необходимы перед стабильным публичным выпуском.

## Сборка

MSYS2 UCRT64, CMake 3.25+, GCC с C++23, Ninja, Qt 6.8+, FFmpeg, ONNX Runtime и GoogleTest.

```bash
cmake --preset ucrt64-release
cmake --build --preset ucrt64-release
ctest --preset ucrt64-release --output-on-failure
```

Команды выполняются в среде **MSYS2 UCRT64** с установленными зависимостями, включая Qt Multimedia. Для сборки portable и установщика нужен Inno Setup 6 и локальные базовые модели:

```powershell
pwsh -File tools/release/build-windows.ps1 -Toolchain 'D:\msys2\ucrt64' -ModelsDirectory 'D:\PF_CUDA\models'
```

Скрипт запускает сборку и тесты, проверяет загрузку настоящего интерфейса из готовой папки, затем создаёт portable ZIP, Setup EXE, ZIP исходников и `SHA256SUMS.txt` в новой папке `release`. Пути к инструментам можно изменить параметрами; [полная инструкция](tools/release/README.md).

Приложение: `build/ucrt64-release/ParallelFinder.exe`. Проверка запуска без UI: `ParallelFinder.exe --pf-smoke`. Тесты входят в репозиторий; тесты ядра не заменяют проверку качества на размеченных видео.

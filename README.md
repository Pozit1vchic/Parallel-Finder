**Parallel Finder** — приложение для Windows, которое ищет монтажные параллели в видео и сценпаках: повторяющиеся движения, похожие позы и положение головы одного персонажа. Можно сравнить найденные моменты в панелях A/B и экспортировать выбранные фрагменты для монтажа.

Видео обрабатывается **локально на компьютере**. Интернет нужен для скачивания отсутствующих моделей и компонентов ускорения. Результаты — кандидаты для просмотра: программа помогает найти моменты, а окончательный выбор остаётся за тобой.

> Актуальная подготовленная сборка: **0.1.0-rc.17**. Это предварительный выпуск. Установщик и portable собираются отдельно; доступные опубликованные версии находятся в [GitHub Releases](https://github.com/Pozit1vchic/Parallel-Finder/releases).

## Что изменилось в rc.18

- **Главный персонаж в сложных ракурсах.** Дополнительное восстановление фрагментов требует нескольких подтверждений лица и отдельной проверки тела. Восстановленный фрагмент не становится доказательством для следующего; непроверенные начало и конец отсекаются.
- **Проверка личности на протяжении фрагмента.** Восстановленные участки ограничиваются подтверждёнными наблюдениями; конфликт лица и слишком большой промежуток между подтверждениями разрывают участок.
- **Диагностика матчера и проверка на исходниках.** Сохранены повторяемые проверки выбора персонажа и причины отклонения конкретных пар. Число найденных результатов не считается доказательством их качества.
- **Правильный пересчёт кэша.** Новая версия не использует старые окна анализа с прежними границами и правилами выбора героя. Первый анализ после обновления может пересчитаться; следующие используют новый кэш.

Матчер всё ещё может пропускать полезные параллели, а главный персонаж — ошибаться при пропущенных склейках или двойных обнаружениях человека. rc.18 улучшает проверенные случаи; полная точность не заявляется.

### Сохранённые исправления rc.17

- **Выдача без повторения одного шота.** По умолчанию каждый исходный монтажный отрезок участвует только в одной паре. Лимит общий для движения, поз и положения головы; повторный поиск его не обходит.
- **Дополнительная проверка главного персонажа.** Трек без лица должен иметь прямое подтверждение по телу с треком, у которого лицо известно. Цепочка похожих костюмов больше не считается доказательством личности. Сцены без выбранного героя по-прежнему пропускаются.
- **Отдельная папка кэша.** Служебные `.pfc` с именами-хешами сохраняются в подпапке `ParallelFinder-cache` выбранной папки кэша. Старые записи переносятся только после проверки формата и имени; исходники и посторонние файлы не затрагиваются.
- **Точный экспорт без потерь по умолчанию.** MKV/FFV1 сохраняет декодированные пиксели, разрешение, глубину цвета и исходный звук. MP4 доступен отдельно: точное перекодирование с потерями или копирование потока по ключевым кадрам.
- **Один статус обработки.** Текущий этап показывается один раз в центре, без повторяющихся надписей в верхней и левой панелях.

Сохранены исправления rc.16: статистика выбранного источника и минимум **12 секунд между началами A/B одного видео**. Для разных файлов временное ограничение не применяется.


### Текущий аудит приложения

После rc.17 выполнен большой проход по производительности и надёжности. Проверены переиспользование результатов повторного поиска, ограничение удерживаемых сессий моделей, обработка повреждённого кэша, отмена поиска и безопасная замена скачанных моделей. Дополнительно проверены CPU, CUDA, DirectML и TensorRT, а экспорт без потерь сравнен с исходными кадрами и звуковыми пакетами.

На контрольном наборе из пяти видео повторный анализ сократился с **25,90 до 2,49 с**, с теми же результатами и превью. Это ускорение повторного поиска через кэш: первый анализ по-прежнему зависит от декодирования и inference, а на длинном Soldier Boy один контроль показал замедление 4,85%. Новые локальные сборки не обновляют старые архивы автоматически. Полная точность на неразмеченных видео и производительность всех классов оборудования не заявляются.

## Установка

Нужна **Windows 10/11 x64**. Для обычного запуска не требуются Python, Visual Studio или CUDA Toolkit. Базовый комплект включает компоненты для CPU, YOLO26m-pose, модель сравнения внешнего вида персонажа и две модели для поиска и сравнения лиц. Другие варианты YOLO и GPU-компоненты устанавливаются из приложения.

Открой [GitHub Releases](https://github.com/Pozit1vchic/Parallel-Finder/releases) и выбери вариант приложения:

| Файл | Для чего | Как использовать |
|---|---|---|
| `ParallelFinder-0.1.0-rc.18-Setup-x64.exe` | Обычная установка | Запусти установщик, выбери папку, затем открой приложение из меню «Пуск». |
| `ParallelFinder-0.1.0-rc.18-Portable-x64.zip` | Запуск без установщика | Распакуй **весь архив** в отдельную папку и запусти `ParallelFinder.exe`. |
| `ParallelFinder-0.1.0-rc.18-Source.zip` | Исходный код | Для самостоятельной сборки; готового приложения внутри нет. |
| `SHA256SUMS.txt` | Проверка скачанных файлов | Содержит контрольные суммы SHA-256. |

Не запускай EXE внутри ZIP и не переноси его отдельно от DLL, моделей и других файлов комплекта. При обновлении portable распакуй новую версию в отдельную папку.

**Portable** означает запуск без установки. Настройки, скачанные модели и провайдеры сохраняются в AppData; установленная и portable-версия используют общий пользовательский профиль.

## Первый запуск

1. **Добавь видео** кнопкой, перетаскиванием или выбором папки. Можно добавить один сценпак или несколько файлов.
2. **Дождись проверки провайдера.** Окно открывается раньше, чем заканчивается проверка ускорения. В это время можно добавлять файлы и выбирать настройки.
3. В левой панели выбери **«Баланс»** и **«Гибрид (движение + кадры)»**. Это удобная отправная точка для первого прохода.
4. Раскрой **«Дополнительные настройки»** и проверь модель. По умолчанию используется **YOLO26 · medium**; после смены приложение запоминает выбор. Значок `✓` означает установленную модель, `↓` — необходимость скачивания.
5. Нажми **«Запустить анализ»**. Первый проход извлекает признаки из видео и сохраняет их в кэш, поэтому обычно занимает больше времени, чем повторный.
6. Выбери результат справа и посмотри моменты **A** и **B**. Кнопки под панелями запускают каждый фрагмент отдельно, **«Воспроизвести A/B»** — оба одновременно. Смена пары останавливает воспроизведение.
7. Отметь подходящие пары галочками и нажми **«Экспорт»**.

Чтобы посмотреть статистику конкретного видео, **выбери его карточку в списке источников**. Кадры и длительность относятся к этому файлу; сцены и пары появляются после анализа. Пара между двумя файлами учитывается у каждого из них, а в общей сводке — один раз.

Стрелки **↑ / ↓** переключают результаты в текущем порядке. **«Сортировать по»** меняет порядок выдачи; **«↑ Вверх»** возвращает к первой паре. Галочка отмечает результат для экспорта.

## Как сменить провайдер

**Провайдер** — движок, на котором выполняются модели анализа. Он определяет использование CPU или видеокарты. Модель YOLO и провайдер выбираются отдельно.

Открой **Настройки → Анализ → Провайдер** и выбери нужный вариант:

| Провайдер | Когда выбирать | Что потребуется |
|---|---|---|
| **Auto / Авто** | Чтобы приложение выбрало доступное ускорение | При отсутствии подходящего GPU-провайдера используется CPU. |
| **CPU** | Для первого запуска или если GPU-компоненты недоступны | Работает с базовым комплектом без скачивания ускорителя. |
| **DirectML** | Для совместимых AMD, Intel и NVIDIA | Видеокарта с поддержкой DirectX 12, драйвер и DirectML-компоненты. |
| **CUDA** | Для совместимой NVIDIA | Драйвер NVIDIA и согласованный пакет CUDA/ONNX Runtime. |
| **TensorRT** | Для совместимой NVIDIA с TensorRT | Драйвер и согласованный пакет TensorRT/CUDA/ONNX Runtime; первая подготовка модели может быть долгой. |

### Подключение ускорения по шагам

1. Выбери **DirectML**, **CUDA** или **TensorRT** в списке провайдеров.
2. Посмотри статус под списком. Если провайдер готов, можно запускать новый анализ с этим выбором.
3. Если компонентов нет, нажми **«Скачать компоненты»** и дождись завершения загрузки и проверки пакета. Для этого нужен интернет; GPU-пакеты могут занимать несколько гигабайт.
4. После установки **полностью закрой приложение и открой его снова**. Новые библиотеки активируются при запуске.
5. Вернись в настройки и проверь статус. Кнопка **«Проверить установленные провайдеры»** повторяет проверку доступных компонентов.
6. Запусти анализ. Проверяй строку с фактическим состоянием GPU: выбранное название само по себе не подтверждает, что ускоритель доступен.

Выбор сохраняется. Смена между **уже доступными** провайдерами применяется к следующему анализу; установка нового runtime требует перезапуска. Явно выбранный недоступный провайдер блокирует анализ — выбери **CPU** или **Auto**, если хочешь продолжить без него.

Приложение проверяет размер и SHA-256 загружаемых пакетов. Драйвер видеокарты устанавливается отдельно. Если показано **«Пакет runtime ещё не опубликован в GitHub Releases»**, кнопка не может установить отсутствующий пакет: используй CPU/Auto или [инструкцию ручной установки](docs/GPU-SETUP.md).

CUDA и TensorRT не гарантируют ускорение каждого этапа: кроме моделей, время занимают чтение видео, поиск пар и превью. TensorRT может дольше работать при первом запуске из-за подготовки движка. Сравнивай скорость на одном видео, с одной моделью и одинаковыми настройками; проход из кэша отличается от анализа с нуля.

Для подготовки собственных пакетов: [руководство по публикации провайдеров](docs/provider-packages-howto.md).

## Модели и настройки поиска

### Какую модель выбрать

В приложении доступны pose-модели **YOLOv8, YOLO11 и YOLO26**. Начни с **YOLO26m-pose**, которая включена в текущий комплект.

| Размер | Практический смысл |
|---|---|
| **n / nano** | Меньше нагрузка, быстрее первичная проверка; сложные позы могут определяться хуже. |
| **s / small** | Умеренная нагрузка для повседневного поиска. |
| **m / medium** | Отправная точка для проверки качества. |
| **l / large**, **x / xlarge** | Больше вычислений и памяти; пользу нужно проверять на конкретном видео. |

Большая или более новая модель не гарантирует больше правильных результатов. Выбор отсутствующей модели автоматически запускает скачивание; до успешной установки анализ недоступен. Для повторной попытки выбери её ещё раз. Нужен опубликованный каталог моделей и доступ к сети.

Для ручной подготовки нужна **pose-модель ONNX**. Обычная модель детекции объектов и файл `.pt` не заменяют pose-экспорт. [Подробности о моделях](docs/models.md).

### Что сравнивать

| Состав анализа | Что ищет |
|---|---|
| **Движение** | Похожее изменение позы во времени: жест, поворот, действие. |
| **Статические кадры** | Похожие видимые позы без требования повторения движения. |
| **Гибрид (движение + кадры)** | Оба типа кандидатов. |

На крупных планах результат может быть подписан **«Сходство положения головы»**. Такая пара не означает, что сравнивалось всё тело.

**«Режим точности»** управляет порогами и ранжированием. **«Обработка кадров»** управляет частотой наблюдений. Повышение частоты помогает увидеть короткие действия, но увеличивает время анализа. Рабочие кадры для моделей ограничены 1280×720; исходное видео остаётся неизменным.

**«Повторный поиск»** проверяет больше кандидатов и дополнительные короткие позы. При совместимом кэше наблюдения переиспользуются без повторного запуска YOLO. Поиск может занять больше времени; появление новых пар не гарантировано.

### Как учитывается персонаж

Поиск использует позу, лицо и внешний вид тела. В сценпаке выбирается доминирующий персонаж; сцены без него не должны автоматически переключаться на другого человека. Уверенное противоречие по лицу запрещает связывать персонажей только из-за похожего костюма.

При маленьком или закрытом лице, сильном профиле, перекрытиях и похожей одежде возможны пропуски и ошибки. Отдельного режима «Костюм / маска» в текущем интерфейсе нет. Программа не распознаёт имя персонажа по названию файла.

## Экспорт

Отметь нужные пары галочками → **«Экспорт»** → выбери формат, папку и префикс имени.

| Формат | Результат |
|---|---|
| **Видео / FFMPEG** | MKV без потерь или MP4-фрагменты сторон A и B выбранных пар. |
| **JSON** | Структурированные данные для дальнейшей обработки. |
| **CSV** | Таблица источников, таймкодов и оценок. |
| **TXT** | Текстовый список найденных пар. |

Для видео используется **короткий контекст вокруг найденного совпадения**: обычно 5 секунд, до 6 секунд для более длинного совпадения. Если сама сцена короче, клип ограничивается её длиной. Это длина экспортируемого фрагмента; она не связана с минимальной разницей в 12 секунд между началами пары.

- **«Точно, без потерь · MKV»** — режим по умолчанию. Видео кодируется в FFV1 без потерь декодированных пикселей, без уменьшения разрешения, глубины цвета или частоты кадров. Исходный звук копируется без перекодирования. Размер файлов может быть существенно больше исходника; для монтажа нужен редактор с поддержкой FFV1/MKV.
  Границы видео выбираются по исходным кадрам. Звук копируется целыми пакетами исходного кодека, поэтому его граница может отличаться на длительность аудиопакета; лишний звук от предыдущей точки перемотки не добавляется.
- **«Точно · MP4»** — совместимый MP4 с точным началом и перекодированием в H.264/AAC. Этот режим использует сжатие с потерями.
- **«Быстро»** — MP4 с копированием исходного видеопотока без повторного сжатия. Границы зависят от ключевых кадров и могут отличаться от выбранных таймкодов. Если исходный кодек нельзя поместить в MP4, экспорт сообщает ошибку.
- **«Как в видео»** — порядок по источнику и времени. **«По сортировке»** — порядок результатов.
- **«Совместить все клипы по возрастанию таймкодов»** — один файл из выбранных A/B. Точные дубликаты диапазонов исключаются, частичные перекрытия остаются. **MKV без потерь** объединяет фрагменты одного исходника без изменения формата. Для разных исходников используй отдельные MKV или выбери **MP4**, который приводит размер и FPS к первому клипу, а звук — к stereo/48 kHz.

Экспорт работает в фоне и показывает прогресс. **«Отменить экспорт»** останавливает нарезку; уже готовые отдельные клипы сохраняются. Ускоритель анализа и видеокодировщик — разные компоненты: выбор CUDA/TensorRT сам по себе не гарантирует аппаратный экспорт.

EDL, FCPXML и After Effects JSX пока не доступны в диалоге приложения.

## Кэш и оформление

Настройки, скачанные модели и провайдеры находятся в пользовательском профиле:

```text
%LocalAppData%\ParallelFinder\ParallelFinder\
├── settings.json
├── models\
└── providers\
```

Путь к **кэшу анализа** и его лимит задаются в **Настройки → Анализ**. Внутри выбранной папки создаётся `ParallelFinder-cache`: файлы с хешами и расширением `.pfc` — промежуточные признаки и превью, а не экспортированные клипы. Превью хранятся внутри записей кэша; отдельные временные PNG создаются для показа в интерфейсе и удаляются при завершении сеанса. По умолчанию кэш находится в пользовательской AppData. Если раньше для кэша была выбрана папка с видео, rc.17 перенесёт только проверенные старые записи в свою подпапку. Повторный проход с совместимыми параметрами переиспользует извлечённые признаки. Смена модели, провайдера или параметров извлечения может потребовать нового прохода; старый формат кэша обновляется после нового анализа.

В **Настройки → Оформление** можно выбрать русский или английский язык, шрифт, акцентный цвет, прозрачность и отключить анимации. При отсутствии профиля язык по умолчанию — English. Свой шрифт можно добавить из `.ttf`/`.otf`; Inter и Montserrat автоматически не скачиваются. Сброс оформления не меняет язык и настройки анализа.

## Если что-то не работает

| Ситуация | Что проверить |
|---|---|
| Кнопка анализа недоступна | Добавлены ли видео, завершена ли проверка провайдера, установлена ли выбранная модель. Для недоступного ускорителя выбери CPU или Auto. |
| Ошибка DLL при запуске portable | Распакован ли весь архив и сохранена ли структура папки рядом с EXE. |
| GPU-компоненты установлены, но не активны | Полностью перезапусти программу, проверь драйвер и статус выбранного провайдера. |
| Загрузка модели или runtime не проходит | Проверь интернет и сообщение об ошибке. Отсутствующий пакет в Releases нельзя исправить повторным анализом. |
| Статистика относится к другому файлу | Выбери карточку нужного источника. Сцены и пары доступны после его анализа. |
| Анализ длинного 4K-видео идёт долго | Попробуй меньшую модель или меньшую частоту обработки; для совместимой NVIDIA проверь CUDA/TensorRT. Первый проход обычно дольше повторного. |
| Найдено мало пар или есть ошибочные | Просмотри A/B, попробуй другой профиль/модель. Закрытые лица, перекрытия и короткие действия ограничивают надёжность. |
| Экспорт «Быстро» начинается раньше | Это ограничение копирования по ключевым кадрам. Выбери «Точно». |

**Проценты сходства — оценки алгоритма, а не вероятность правильного результата.** Сходство сцены отражает контекст и не подтверждает повтор движения. Количество пар также не измеряет качество поиска.

## Сборка из исходников

Нужны MSYS2 UCRT64, CMake 3.25+, GCC с C++23, Ninja, Qt 6.8+ с Qt Multimedia, FFmpeg, ONNX Runtime и GoogleTest.

В среде **MSYS2 UCRT64**:

```bash
cmake --preset ucrt64-release
cmake --build --preset ucrt64-release
ctest --preset ucrt64-release --output-on-failure
```

Приложение создаётся в `build/ucrt64-release/ParallelFinder.exe`. Проверка запуска без UI: `ParallelFinder.exe --pf-smoke`.

Для установщика и portable дополнительно нужны Inno Setup 6 и локальная папка базовых моделей. Пример для PowerShell; пути замени на свои:

```powershell
pwsh -File tools/release/build-windows.ps1 -ReleaseTag '0.1.0-rc.18' -Toolchain 'D:\msys2\ucrt64' -ModelsDirectory 'D:\PF_CUDA\models'
```

Скрипт собирает приложение, запускает тесты и проверяет запуск упакованного UI. Затем создаёт Setup EXE, Portable ZIP, архив исходников и `SHA256SUMS.txt` в новой папке `release`. [Полная инструкция по сборке релиза](tools/release/README.md).

# RC.17: выдача, персонаж, кэш и экспорт

## Поведение

- По умолчанию один исходный шот участвует в одной паре. Лимит общий для движений и статических сравнений; расширенный поиск не отключает его. API и диагностический `PF_RESULTS_PER_SHOT` могут явно разрешить повторное использование.
- Квота применяется также к окнам без sceneIndex: при известных границах используется общий диапазон сцены, иначе отдельное окно. Результаты не отбрасываются только из-за похожего фона.
- При выборе главного персонажа сначала проверяются связи с известными лицами. Треки без лица присоединяются по прямой связи с таким треком, а не по цепочке похожей одежды. Противоречие по лицу и одновременная видимость по-прежнему запрещают объединение.
- Производный кэш имеет контракт `motion-v39|direct-face-anchor`. Старые результаты требуют нового анализа.
- `.pfc` помещаются в подпапку `ParallelFinder-cache`. Из прежнего корня переносятся только записи с корректным PFCACHE1, версией, размером и именем SHA-256 от сохранённого ключа. Другие файлы не перемещаются и не удаляются.
- Во время анализа этап показывается одной надписью в центре. Верхняя и левая панели не дублируют его.

## Экспорт без потерь

В диалоге по умолчанию выбран «Точно, без потерь · MKV». Используется FFV1 level 3, исходный формат пикселей, сохранение временных меток кадров и копирование аудиопотока. Нет фильтра уменьшения, принудительного yuv420p/8-bit или нового AAC-сжатия.

MP4 «Точно» остаётся совместимым режимом с потерями H.264/AAC. «Быстро» копирует поток без повторного сжатия, но не гарантирует точные границы между ключевыми кадрами.

Объединение без потерь поддерживает фрагменты одного исходника: никакого приведения размера, FPS или звука к другому формату. Смешанные исходники в этом режиме отклоняются с понятным сообщением. Для них доступны отдельные MKV либо совместимый MP4 с нормализацией. FFV1/MKV требует поддержки со стороны монтажного приложения и обычно занимает больше места, чем исходный H.264/HEVC.

## Проверки

- CTest: 5/5, включая ядро, QML/UI, запуск приложения, изоляцию запуска и регрессии матчера.
- Тест цепочки одежды проверяет обе перестановки промежуточных треков.
- Квота проверяется для движения и поз одновременно, включая расширенный поиск.
- Тест кэша проверяет перенос собственных записей и сохранность видео и постороннего `.pfc`.
- Тест точного 10-битного экспорта сравнивает декодированные пиксели побайтно, проверяет yuv420p10le, размеры и исходный PCM 44100 Hz.
- На пользовательском Soldier Boy 3840×1600 проверен точный секундный MKV-фрагмент: все хеши декодированных кадров совпали с исходником.
- Проверено объединение MKV без изменения геометрии/FPS, удаление точных дублей и отказ от нормализации смешанных источников.
- QML-тест проверяет выбор MKV по умолчанию, переключение режимов и сохранение MKV при объединении. Диалог экспорта просмотрен на снимке интерфейса.

## Границы проверки

Одно использование шота устраняет повторение одного монтажного отрезка в карточках, но не доказывает смысловое сходство действий. Прямое подтверждение личности уменьшает риск цепочек по одежде; закрытые лица, профиль и похожие костюмы всё ещё могут приводить к пропускам и ошибкам. Это предварительный выпуск, а не оценка precision/recall на независимом наборе видео.

## Полный Soldier Boy

Финальная сборка: `0.1.0-rc.17`, CUDA, YOLO26m-pose, fast, combined, новый пустой кэш. Источник пользователя: Soldier Boy S03, 2641,1385 с, 3840×1600.

- rc.16: 96 пар; rc.17: 52 пары. Уменьшение количества отражает ограничение повторов, а не измеренную точность.
- Максимум участий каждого исходного шота: 1, общий для обоих типов результатов.
- Минимальная разница начал A/B в одном источнике: 12,8461667 с.
- Контрольные Soldier Boy 00:28:50 / 00:37:59 и 00:14:33 / 00:20:26 сохранены.
- Контрольные неправильные пары Хоумлендера, Старлайт, ММ и смешанная лесная пара не найдены.
- Все 2110 окон принадлежат выбранным трекам главного персонажа; количество допущенных треков — 264.
- Просмотрены кадры обеих сторон всех 52 результатов. Это обзор персонажа и состава выдачи, не покадровая оценка сходства действий.
- Первый полный проход — 296057 мс на текущем ПК; это локальный замер, не обещание скорости на другой конфигурации.

Диагностика, эмбеддинги и контактные листы хранятся только в ignored `build/rc17-audit`, в дистрибутив и исходный архив не включаются.

# Запуск, превью и полнота отбора кандидатов — RC.10

Дата: 30 сентября 2026. База сравнения: `13ae09a`, сборка RC.9. Машина: Core Ultra 7 270K Plus, RTX 5070, Windows x64. Модель: опубликованная `release-models/yolo26m-pose.onnx`; runtime CUDA и те же ReID/face weights, без снижения частоты анализа.

## Что изменено

Проверка реальных ORT-сессий перенесена за первый представленный кадр окна и выполняется в фоне. Простого запуска потока перед QML оказалось недостаточно: driver initialization конкурировала с рендерером. Плашка показывает проверку, запуск анализа временно недоступен. Результат проверки публикуется одним снимком для QML; вызовы backendAvailable не захватывают mutex выполняющейся проверки. Ошибки не превращаются в фиктивную готовность GPU.

MediaPlayer и VideoOutput не создаются в пустом рабочем пространстве. При выборе результата создаются оба плеера, при очистке уничтожаются; смена пары останавливает воспроизведение. Это не переход на внешний плеер. Тест декодирует настоящий MP4, проверяет отдельные кнопки и общий запуск A/B.

Превью сохраняются с прежним потолком 1920×1080, но полный 4K RGBA больше не материализуется перед уменьшением. PNG остаётся lossless: QImageWriter compression=12 соответствует zlib level 1 в текущей Qt. [Официальная реализация Qt PNG](https://raw.githubusercontent.com/qt/qtbase/6.11/src/gui/image/qpnghandler.cpp) задаёт отображение 0..100 в 0..9; compression=1 означало бы level 0, а не level 1. Отдельный тест подтверждает равенство всех RGBA-пикселей после сохранения/чтения и отсутствие изменения исходного буфера. Это проверка сжатия, не побитовое равенство нового и старого resize.

Inference-буфер перемещается в pending sample вместо второго копирования; время жизни остаётся достаточным для pose/ReID/face inference. Нейросети и рабочее разрешение анализа не менялись.

## Замеры

Все длительности анализа ниже берутся из настоящего контроллера. Startup-smoke проверяет представление окна; новая версия дополнительно дожидается опубликованной готовности backend.

| Метрика | RC.9 | RC.10 |
|---|---:|---:|
| Полный цикл startup-smoke, 3 повторных запуска | 2057 / 2039 / 2059 мс | 1312 / 1186 / 1178 мс |
| Первый кадр от входа в main | отдельный счётчик отсутствует | 934 / 828 / 818 мс |
| Готовность backend от входа в main | отдельный счётчик отсутствует | 1171 / 1045 / 1040 мс |
| Soldier, весь повторный анализ, cache_hit=1 | 25,551 с | 14,146 с |
| Soldier, 71 превью | 17,831 с | 7,263 с |
| Soldier, matcher | 1,209 с | 1,186 с |

Полное время startup включает загрузку DLL и завершение процесса, firstFrameMs — нет. Эти столбцы не используются как взаимозаменяемые. Один первый прогон с CUDA дал 1049 мс до кадра и 2107 мс до backend; следующие быстрее благодаря прогретым системным/драйверным кэшам. Ни холодный запуск Windows после перезагрузки, ни слабые ПК не измерены.

Холодный Soldier в новой версии: **47,874 с**, cache_hit=0, 16 190 декодированных кадров, 2159 RGBA-конверсий, 83 результата, 71 превью за 7,193 с. Для получения нового cache key использована отдельная копия тех же ReID weights в ignored build-папке; пользовательский кэш не очищен и настройки не изменены. До исправления холодный RC.9: 58,479 с, но это одиночные прогоны, а не статистика производительности.

Dean (4K): повторный анализ **3,332 с**, 7 результатов, 9 превью за 897 мс. Для отдельных фаз и CPU/GPU нагрузок нужен более длинный набор: общая скорость зависит от числа выбранных кадров, лиц и результатов.

## Matcher: исправлен конкретный пропуск

Раньше pose ANN мог заполнить полезный лимит позами чужих людей. Более поздняя проверка личности их отклоняла, а похожая поза нужного персонажа оставалась за пределами списка. Теперь перед подсчётом полезных слотов применяется **та же** identity-проверка, что в окончательном сравнении. Если requireAppearance отключён и нет обязательной межтрековой проверки, ранний фильтр также отключён. Дополнительные DTW-сравнения по-прежнему ограничены; алгоритм не превращён в полный O(N²) перебор.

Регрессия `ContradictoryPeopleCannotConsumePoseRetrievalBudget` содержит правильную пару, 320 чужих face embeddings и 280 похожих identity-кандидатов с неподходящей позой. Прямое сравнение правильной пары проходит порог; прямое сравнение ложной позы — нет. До исправления all-pairs retrieval пропускал правильную пару в обоих порядках данных, после находит в обоих. Тест большой очереди занимает примерно 1,8 с против 1,4 с до изменения: улучшение полноты не выдаётся за ускорение самого ANN.

Контроль реальных видео:

- Dean: 7 пар, точное равенство таймкодов, типов и similarity с RC.9; положительные 3/3, отмеченные ложные 0/3.
- Soldier: 83 пары, положительные 3/3, отмеченные ложные 0/5, и на новом холодном прогоне тоже. Относительно RC.9 кандидат 85 / 254,5 с заменился кандидатом 79 / 232,5 с; новый кандидат ещё требует человеческой разметки. Совпадение общего числа пар не означает идентичный список.
- Проценты и пороги не менялись. Новая полнота доказана на конкретной регрессии, глобальная точность и «идеальные параллели» не заявляются.

## Как повторить

Для startup запустите `tools/benchmark/run_startup_smoke.ps1 -Exe <exe> -ReportPath <json>` из окружения, в котором приложение может найти Qt и выбранный runtime. Скрипт не меняет постоянные настройки. Для автономной проверки пакета удалите developer Qt/DLL пути из окружения и используйте полный staging-каталог.

Для видео: `tools/benchmark/run_analysis_smoke.ps1` с явными Video, Exe, Model, OrtDll, ReIdModel, Provider=cuda, Modes=combined, ReportPath. При `PF_DEBUG_ANALYSIS=1` JSON сохраняет decodeDiagnostics (включая cache_hit) и timingDiagnostics. Затем запустите `check_reference_pairs.ps1`, для Dean передайте `-ReferencePath tools/benchmark/dean-reference.json`. Контрольные отчёты этой проверки находятся в ignored `build/rc10-*-report.json`.

CTest: 5/5 наборов. Ошибки ORT из неполного внешнего тестового PATH не обходятся настройками матчера; обычное приложение добавляет выбранный provider directory само. При закрытии во время ORT initialization поток безопасно присоединяется: ожидание драйвера может задержать завершение, принудительного убийства потока нет.

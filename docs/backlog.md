## 2026-10-10 — классификация и границы клипов

- [x] **Временная классификация по реальным сценпакам с приоритетом поворотов головы и тела.** Добавлены отдельные классы и проверка обеих сторон пары; движения камеры, возврат руки, скрытые суставы и вставание учитываются отдельно. Проверены 11 вручную просмотренных примеров Elliot/Soldier и преобразования этих наблюдений; неоднозначные действия остаются неопределёнными. Подробности: [movement-grouping-2026-10-10.md](movement-grouping-2026-10-10.md).
- [ ] **Измеримая профессиональная точность на разных сценпаках.** Текущая классификация использует геометрические признаки временной последовательности поз. Требуются отдельная разметка, независимая выборка и оценка ошибок по классам; небольшой набор регрессионных примеров не подтверждает точность на всём материале.
- [x] **Группировка по типам движений вместо цветов.** Список по умолчанию разбит на типы; доступны фильтр, ручная смена типа и отмена действия. Автоматическая классификация использует только совпавший интервал движения. Отдельные клипы экспортируются в пронумерованные папки типов с типом в имени; общий ролик следует выбранному порядку типов. Неопределённые и смешанные движения не получают выдуманного точного типа.
- [x] **Нарезка только совпавшего интервала.** Убраны автоматическое добавление пяти секунд окружения и обрезание длинной параллели до шести секунд. «Точно» использует поддержанный матчем диапазон; для одиночной позы сохраняется один кадр. При копировании без потери качества начало остаётся привязано к ключевому кадру исходника.
- [x] **Окно ошибки Qt от pfui_tests.** Для проверок интерфейса, обновлений и запуска приложения задан каталог платформенных плагинов SDK; пакетный `qt.conf` больше не мешает запуску offscreen-проверок.

Подробности: [export-classification-fixes-2026-10-10.md](export-classification-fixes-2026-10-10.md).

## 2026-10-10 — производительность и понятный ход поиска

- [x] **Повторная классификация одних окон в плотном списке кандидатов.** Тип каждого окна вычисляется один раз за проход; отбор, расширение пар и финальная проверка используют готовые результаты. Замер на миллионе пар из 64 окон: 639.9 мс → 5.38 мс при одинаковых типах и значениях уверенности. Это замер одного этапа, не всего анализа.
- [x] **Лишние проверки идентичности при удалении дублей.** Сначала исключаются пары из заведомо разных сцен, затем проверяется человек. Правила принятия и отбраковки совпадений сохранены.
- [x] **Повторное чтение подготовленных клипов при склейке.** Длительность потоков вычисляется в том же проходе, который готовит HEVC-стык; отдельный повторный проход больше не нужен. Для MP4 с полными метаданными не запускается лишнее декодирование для повторного определения параметров; неполные заголовки сохраняют обычную проверку FFmpeg.
- [x] **Одинаковая надпись с разными счётчиками дополнительного поиска.** Теперь вторичный проход показывает конкретный этап: подготовку, поиск кандидатов, сравнение или отбор. Отмена и передача прогресса сохранены.

Первоначально полный замер не проводился; при последующем аудите выполнен весь поиск на копии готового кэша шестичасового Elliot и первые анализы двух разных сценпаков. Полный поиск ускорился в 1,77 раза при точном совпадении 191 результата; первые анализы — примерно в 1,44–1,54 раза. Кэш сохранён. Подробности: [analysis-audit-2026-10-10.md](analysis-audit-2026-10-10.md).

- [ ] **Ускорение всего анализа вдвое без снижения качества.** Текущие полные замеры не достигают 2×; улучшения отдельных операций не закрывают это требование. Нужен дальнейший профиль декодирования/нейросетей и точных сравнений на длинных источниках.
- [x] **Разные изображения H.264 у CPU и GPU при одинаковом времени.** Дополнительная проверка Soldier Boy выявила расхождение порядка кадров в CUVID. Для декодирования H.264 без аппаратного уменьшения используется парсер FFmpeg с CUDA-поверхностями; строгая проверка кадров, VFR, полного диапазона цвета и перемоток прошла. Подробности в отчёте аудита выше.

## 2026-10-10 — разбор результатов

Статус: 2026-10-10 пользователь поручил пересмотр существующих функций; три недочёта ниже исправлены и проверены.

- [x] **Выбор пары после удаления через Delete / Backspace или кнопку в карточке.** Оба способа удаления возвращают просмотр на первую пару, что мешает последовательному разбору результатов. При будущем исправлении сохранить позицию в списке и переходить к соседней оставшейся паре, а не сбрасывать выбор на начало.
- [x] **Перевод названия цвета в карточке результата.** При переключении языка интерфейса название назначенного паре цвета остаётся на русском: например, «Красный» при английском интерфейсе. Название цвета должно соответствовать текущему языку интерфейса и обновляться при его переключении.
- [x] **Устаревшее название после смены цвета пары.** Если сначала назначить красный или другой цвет, а затем заменить его, цветной маркер обновляется, но название остаётся от предыдущего цвета. На скриншоте синий и зелёный маркеры подписаны «Red». При будущем исправлении текст должен сразу соответствовать текущему назначенному цвету. Это отдельное проявление от проблемы перевода при смене языка; общая причина пока не проверена.

Причины и проверка исправлений описаны в review-polish-2026-10-10.md.

## Одобренные идеи — реализовано 2026-10-10

- [x] **Палитра акцентного цвета оформления.** Уточнение пользователя: палитра только в «Настройки → Оформление → Акцентный цвет»; выбор цветов пар остаётся прежним.
- [x] **Отмена последнего действия через Ctrl+Z.** Возвращать удалённые пары, предыдущие цвета и границы после ручной подстройки. Учесть команду в настройках горячих клавиш.
- [x] **Следующая неразобранная пара.** Команда перехода к следующей неразобранной паре; состояние просмотра независимо от цвета и избранного. Пара считается разобранной только после явной отметки кнопкой или горячей клавишей R; открытие, цвет и избранное этот статус не меняют.
- [x] **Поиск и выделение результатов по исходному видео / сценпаку.** Показывать, из каких сценпаков пришла каждая сторона пары; искать результаты по имени исходника и позволять выделять соответствующие пары. Учитывать обе стороны A/B.

Не включать в план: повтор A/B по кругу, быстрый просмотр окружения кадра и пользовательские имена цветовых меток — пользователь отклонил эти предложения.

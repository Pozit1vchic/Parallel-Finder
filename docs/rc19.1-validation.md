# RC19.1 camera-selection validation

## Scope

This change accelerates result selection and returning-camera verification. It does not change model inference, candidate budgets, pose thresholds, identity gates, pixel thresholds or the requirement for three measured source frames. Decoding and recognition are excluded from the full-input replay timings below; source observations from the earlier complete 521,399-frame Elliot analysis are reused with the same expanded policy.

Hardware and source details are recorded in [RC19 validation](rc19-validation.md). Native process resource polling uses a two-second interval. Intermediate diagnostic trials remain in ignored build directories and are not published benchmarks.

## Exact decisions with less work

Returning-body camera verification is deferred until an edge can survive occupied-shot and NMS checks, or can participate in an augmenting path. Augmentation visits the first camera-valid hypothesis for each neighbor in the original ranking order, including a later head/motion hypothesis if a returning-body hypothesis is rejected. Body proofs keep canonical shot orientation. No body/pose edge admitted into a result bypasses its original camera proof.

Portrait selection checks cheap conflicts across all kept pairs before checking source sequences. Existing exact returning-camera decisions are reused; camera families are not combined transitively. Unavailable alternatives are omitted after their shots are occupied. Remaining alternatives borrow immutable match records instead of copying all source paths and scores. The result vector reserves capacity for disjoint results instead of every raw hypothesis.

Exact representative-thumbnail comparisons are memoized per ordered shot pair. Two-bit packed states retain unknown/false/true separately, including orientation, with a 16 MiB state-payload maximum. Large shot sets use a bounded sparse fallback with a conservative entry budget. These caches live for one search, alongside the existing source-frame and matcher reuse caches, and are released with that search. The recovery search has its own bound. Cache keys do not establish additional camera equivalence.

## Completed checks

- All 101 matcher tests pass, including duplicate suppression, distinct-setting controls, measured face vetoes, progress on the caller thread and cancellation.
- Eight replications of the measured returning-camera fixture preserve the shipped RC19's 16 distinct-setting pairs and reject its returning body cameras. This synthetic scheduling/cache test crosses packed-cache column boundaries; it is not independent recall evidence.
- Six executable A/B comparisons against the shipped RC19 matcher probe preserve every result field and ordering: limits 1, 2, 5 and 100, a coverage seed of 2, and unused-shot recovery. These small inputs show correctness, not a large speedup.
- Final Soldier and five-source replays preserve the preceding RC19's six and two results respectively, with every matcher field and ordering equal. The five-source case includes three Elliot excerpts, a copied pack and Soldier as a foreign-person control. These short replays are too brief for a meaningful sampled peak-memory claim.
- The first complete deferred/cheap-check replay, before the representative memo, returned all 187 RC19 pairs with all matcher fields and ordering equal. Application time was 725,568 ms versus 1,820,158 ms for RC19; matcher time was 722,073 ms versus 1,790,747 ms. Peak sampled working set was 4,546,465,792 bytes, private bytes 5,194,674,176 bytes. All 374 previews were already cached.

The final RC19.1 binary completed the same full-input replay in **717,328 ms application time (11 min 57.328 s)**; matcher time was **712,644 ms**, versus **1,790,747 ms** for RC19, a measured **2.513x matcher speedup**. All **187 matcher results and their ordering are exactly equal**, including intervals, scores and classifications; only preview file URLs differ. RC19 generated 37 new images under temporary timestamp/index names; RC19.1 restored all 374 previews under cache-key filenames in a different temporary session directory. This does not change matching intervals. The same 19,109,990 primary comparisons and 1,073,584 raw accepted hypotheses were retained. The final pass recorded 209,894 representative checks and 55,860,979 exact memo hits. The added packed cache in that pass occupied 533,968 bytes; this is not total process memory. Peak sampled working set was 4,540,129,280 bytes; private bytes 5,195,874,304 bytes, with 359 samples.

The intermediate deferred-only run was stopped after identifying the remaining portrait bottleneck; one short stale-link diagnostic was also stopped and rebuilt. Neither incomplete trial is included in successful timings. The small repeated-fixture recovery case did not demonstrate acceleration; this optimization primarily helps the large selected-camera workload.

All six CTest targets, isolated packaged native startup and the signed archive installation/health check are mandatory release-script gates; a failed gate refuses packaging. Their final logs accompany the local artifacts.

## Limits

This performance correction preserves the existing result policy; it does not solve the independent five-example Soldier recall deficit, photographed faces, tracker actor transitions or every remaining duplicate described in RC19 validation. Preserving an existing result list is not proof of exhaustive recall or absence of false positives. A currently running older executable must finish or be cancelled normally; the fix takes effect in the new executable and a new analysis.

# MCP в Parallel Finder

В «Настройки → Система» включи **MCP-сервер**, затем нажми **Скопировать подключение**. В буфере будет JSON с адресом и заголовком доступа для MCP-клиента. По умолчанию адрес — `http://127.0.0.1:32145/mcp`; порт можно изменить. В настройках видно, запущен ли сервер; занятый порт показывается как ошибка, а не как успешный запуск.

Сервер работает, пока открыто приложение. Он слушает только этот компьютер и требует ключ доступа. Ключ сохраняется в настройках; кнопка **Обновить ключ** отзывает прежнее подключение. Не публикуй скопированную конфигурацию: она содержит ключ. После изменения доступных команд обнови подключение в клиенте.

Без дополнительных разрешений доступны три команды:

- `pf_get_status` — состояние анализа и экспорта, прогресс и сводки исходников.
- `pf_list_results` — результаты в порядке классов движений; фильтр `classification`, страницы `offset`/`limit` (до 200 записей).
- `pf_list_classes` — доступные типы и число результатов каждого типа.

Переключатель **Разрешить управление приложением** добавляет команды:

- `pf_set_classification` — ручной тип для выбранных ID.
- `pf_set_clip_range` — границы A/B с обычной проверкой допустимых интервалов в приложении.
- `pf_set_review` — отметки избранного и просмотренного.
- `pf_start_analysis` / `pf_cancel_analysis` — запуск по существующим абсолютным путям и отмена анализа.
- `pf_export_results` / `pf_cancel_export` — экспорт выбранных результатов и отмена. Отдельные клипы группируются по типам; `montage: true` создаёт общий ролик в том же порядке. Занятые имена получают числовой суффикс.

В экспорте `mode: "lossless"` копирует исходные потоки: качество сохраняется, начало зависит от ключевых кадров. `mode: "exact"` точно режет с перекодированием в максимальном доступном режиме качества. Эти ограничения совпадают с окном экспорта приложения. Папка назначения должна существовать; инструмент не запускает произвольные команды и не удаляет кеш.

Длительные операции возвращают ответ сразу после принятия; ход работы проверяется через `pf_get_status`. Он показывает отдельно анализ (`busy`), подготовку превью после ручной правки (`reviewBusy`), экспорт (`exportBusy`) и разрешение управления (`controlAllowed`). Новая операция или правки во время анализа/экспорта/подготовки превью отклоняются. Ошибки инструментов возвращаются с `isError: true`; неверные ID, типы и аргументы не преобразуются в успешные действия. Запуск нового анализа отмечен в метаданных MCP как действие, заменяющее текущие результаты.

Транспорт — stateless Streamable HTTP с JSON-ответами, протоколы `2025-06-18` и `2025-11-25`. GET-поток не используется (405), уведомления принимаются с 202. Проверяются Host/Origin, ключ, версия протокола, однозначная длина запроса и ограничение 1 MiB. Неполный запрос закрывается через 10 секунд; одновременно допускается до 32 подключений.

Завершение экспорта отражается в `exportSuccess` и `exportMessage` ответа `pf_get_status`, включая отмену и сообщения FFmpeg. До получения результата или во время нового экспорта `exportSuccess` равен `null`: один только `exportBusy: false` не означает успешное завершение.

Совместимость проверена официальным Python SDK `mcp 1.30.0`: initialize, tools/list и вызовы всех команд чтения. Протокол и требования к локальному транспорту: [MCP Streamable HTTP](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/basic/transports.mdx).

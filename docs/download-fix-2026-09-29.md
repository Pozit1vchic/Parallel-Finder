# Загрузка моделей и GPU runtime: исправление 29 сентября 2026

GitHub Releases выдаёт файлы через HTTP 302 на `release-assets.githubusercontent.com`.
Загрузчик проверял метаданные промежуточного ответа как окончательные и сам
вызывал `abort()`. Qt показывал это как `Operation canceled`, хотя пользователь
ничего не отменял. Кроме того, общий таймер обрывал любой архив через 120 секунд,
что недостаточно для CUDA (1,65 ГБ) и TensorRT (3,30 ГБ в двух частях).

Исправлено:

- Редирект разрешается только на доверенный HTTPS-хост; промежуточный 3xx не
  записывается в `.part` и не считается окончательным ответом.
- Ошибочный HTTP-статус и превышение лимита размера теперь сообщаются явно,
  вместо маскирующего `Operation canceled`.
- Для передачи действует 60-секундный таймер отсутствия данных и двухчасовой
  верхний предел, а не двухминутный предел на всю загрузку.
- Для манифестов увеличен лимит ожидания с 15 до 90 секунд и добавлена проверка
  хоста перенаправления.
- Путь к `.part` строится через файловый путь, чтобы не портить Unicode-имена
  пользовательских папок Windows.

Проверки: полный CTest 5/5; отдельные сетевые тесты реально скачали файл
GitHub Release через 302, модель YOLO26n и архив DML, сверили размер и SHA-256;
манифест CUDA получен из опубликованного `runtime-v1`. Гигабайтные CUDA и
TensorRT целиком не скачивались в этом прогоне. После установки RC необходимо
повторить загрузку у пользователя на его сети и проверить активацию провайдера.

В тот же RC включены два небольших исправления состояния интерфейса. Изменение
списка источников немедленно очищает результаты и все зависимые счётчики; старый
фоновый анализ больше не может вернуть число пар после удаления видео. Выпадающий
список акцентного цвета при каждом открытии настроек синхронизируется с реально
сохранённым цветом, а не остаётся визуально на «Оранжевом».

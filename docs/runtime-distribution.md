# Пакеты CUDA и TensorRT для Parallel Finder

Проверено по документации ONNX Runtime/NVIDIA 2026-09-20. Версии фиксируются в пакете, а не подбираются пользователем.

## Рекомендуемая схема

1. Сначала выбрать конкретную Windows x64 сборку ONNX Runtime. Сверить её CUDA/cuDNN/TensorRT зависимости по официальным таблицам.
2. Собрать минимальный набор разрешённых к распространению runtime DLL. Не копировать весь Toolkit, Python environment, драйвер или случайные DLL из разных версий.
3. CUDA-пакет содержит ORT, CUDA EP, общий provider DLL и необходимые CUDA/cuDNN библиотеки. TensorRT-пакет дополнительно содержит совместимый TensorRT EP и библиотеки TensorRT, а также CUDA fallback.
4. Все взаимозависимые DLL расположить рядом с onnxruntime.dll. Вложенная папка допускается загрузчиком. Добавить LICENSE/NOTICE и точный перечень версий.
5. Протестировать на чистой машине с поддерживаемой NVIDIA и драйвером: загрузка DLL недостаточна; нужен реальный inference с журналом выбранного провайдера.
6. Создать ZIP, измерить его размер и SHA-256. Заполнить providers.json по providers/providers.example.json. Заглушки недопустимы.
7. Разместить ZIP и providers.json как assets отдельного GitHub Release с тегом runtime-v1. В приложении используется фиксированный URL этого тега, а не releases/latest.
8. Пользователь нажимает «Скачать runtime», загрузчик проверяет размер/хэш и структуру архива, устанавливает в <папка приложения>/providers/<provider>, пишет active.txt. Перезапуск обязателен для смены уже загруженного ORT.

Не меняем системный PATH и не устанавливаем CUDA Toolkit в Windows. Для пользовательской установки папка приложения должна быть доступна для записи. Драйвер NVIDIA устанавливается отдельно официальным установщиком NVIDIA; приложение не заменяет драйвер.

## Совместимость и скорость

cuDNN 8 и 9 не взаимозаменяемы. Таблица TensorRT зависит от конкретного ORT. Не брать «самые свежие» версии каждого компонента независимо.

TensorRT оптимизирует модель под окружение, поэтому первый запуск может быть долгим. Кэш engine нельзя считать универсальным для любых GPU и версий. Проверять скорость после прогрева и отдельно измерять полный анализ, а не только inference. Auto/доступный provider — ещё не доказательство, что все операции выполняются на GPU.

## Лицензионный стоп перед публикацией

Код Parallel Finder — AGPL-3.0. CUDA, cuDNN и TensorRT имеют отдельные условия. Публичная доступность DLL не означает свободное право перепубликовать их рядом с AGPL-приложением. Требуется проверка разрешённых redistributables, совместимости условий и необходимых уведомлений. Не добавлять произвольное исключение к лицензии чужого кода.

Пока это не подтверждено, NVIDIA runtime-пакеты не публикуются. Альтернатива для дальнейшей реализации — официальный источник скачивания с соблюдением условий NVIDIA; текущий загрузчик принимает GitHub URLs, и для такой схемы его понадобится отдельно изменить.

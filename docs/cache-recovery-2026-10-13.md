# Обнаруженное отсутствие прежнего кеша и восстановление

После исчезновения сессии полного замера и процесса приложения проверка снимка `build/movement-review/current-cache-before-fixes.xml` обнаружила отсутствие всех 871 прежних `.pfc` в `D:/tmp`. Ранее в этой работе проверка показывала 0 изменённых/отсутствующих файлов. Точное время и причина исчезновения не установлены. Отсутствие итогового процесса/отчёта не доказывает связь с исчезновением кеша. Просмотр событий Windows не дал доступного подтверждения причины.

Сохранённые копии в `build/performance-audit` проверены по имени, размеру и времени записи против снимка. Найдены 261 соответствующий файл, восстановлены только отсутствующие назначения посредством копирования с запретом перезаписи. Манифест: `build/movement-review/cache-recovery-manifest-20261013.json`. 610 файлов из прежнего снимка пока не найдены; полная сохранность всего старого кеша сейчас не подтверждена. Проверка доступных метаданных корзины не обнаружила записей для `D:/tmp`.

Отдельный полный анализ Elliot сохранился в `build/movement-review/cold-auto-nvdec-cache-20261013`. Три завершённых `.pfc` с подготовленными данными дополнительно скопированы в `D:/tmp` без замены существующих файлов. Это новые сохранённые данные, а не восстановленные под прежними именами 610 файлов. Два больших файла наблюдений совпадают по SHA-256 с предыдущим полным замером (см. `nvdec-conversion-performance-2026-10-13.md`).

Повторная проверка приложения на отдельном кеше завершилась за 677 695 мс (11,29 минуты), подтверждает `complete_cache_hit=1`, `window_cache_hit=1`, `decoded=0`, 3928 сцен и 175 результатов. Все 175 пар совпали с предыдущим завершённым замером по исходникам, сторонам, типу и точным границам интервалов; классификации в этом наборе также совпали. Отчёт: `warm-after-vertical-walking-20261013.json`, сравнение: `warm-after-vertical-walking-comparison-20261013.json`. Это доказывает возможность повторного поиска без нового декодирования на этом кеше; автоматическое попадание в кеш любой старой публичной сборки и с другими настройками не проверено.

Восстановление не удаляло и не заменяло файлы. После этой проверки пользователь подтвердил, что сам удалил `tmp`, чтобы освободить место. Причина отсутствия прежнего набора установлена: намеренная очистка пользователем; это не свидетельство удаления кеша приложением. Дальнейшее восстановление остановлено. Уже скопированные 264 файла оставлены на месте, автоматическое повторное удаление не выполнялось. Отсутствие итогового отчёта холодного замера остаётся отдельным фактом и этим пояснением не объясняется.

# RC18.8 performance and regression checks

This release changes scene preparation, identity clustering, camera-comparison work and progress reporting. It does not lower identity thresholds, disable duplicate suppression, or promise more accepted pairs. Performance probes are distinct from labelled accuracy tests.

| Check | RC18.7 | RC18.8 | Result preservation |
| --- | ---: | ---: | --- |
| Scene detector, 20,000 synthetic thumbnails | 763 ms; 1,095.7 MB peak process working set | 633 ms; 40.0 MB | All 1,407 boundaries and scores exactly equal |
| Dominant identity selection, 1,500 synthetic tracks with 512-dimensional prototypes | 1,457 ms | 261 ms | Same 300 admitted track IDs |
| Head matcher, 100 windows across 5 sources, 60 frames per measured sequence | 22,899 ms | 13,135 ms | All 43 pairs exactly equal |
| Body matcher, 300 windows across 5 sources | 4,841 ms | 4,847 ms | All 149 pairs exactly equal; no measured speed gain |
| Actual HEVC, 300 view targets across a 15-minute interval, 8 CPU threads in total | 245,715 ms | 109,414 ms | Native timestamps and RGB descriptors equal byte for byte |
| Actual HEVC, the 78 view targets selected by the full analysis | 47,762 ms | 36,057 ms | Independent, adaptive single-reader and parallel outputs equal byte for byte; single-reader time 44,332 ms |
| Full cold CUDA analysis of that 15-minute interval | 243,631 ms | 220,097 ms | All 15 pair records exactly equal, excluding temporary preview paths |
| Warm analysis of a cloned legacy cache, same input and settings | 2,917 ms | 2,956 ms | Both pairs exactly equal; no inference rerun or view decoding |

The full cold timings include inference, video decoding, face verification, matching and previews. The controlled candidate run took 220,097 ms versus the baseline's 243,631 ms, with analysis counters enabled and detailed matcher logging disabled. Earlier candidate runs took 269,674 ms while overlapping tests and 400,630 ms with detailed matcher logging (204 MB of output); those conditions are not used for the final speed comparison. All three candidate runs preserved the same 15 pair records. These are single-run measurements, not a speed guarantee for every scene pack. The separately measured camera/identity improvements must not be presented as an end-to-end multiplier. CUDA performs recognition; this HEVC source retains the validated CPU decoder fallback because its color format is not admitted by the NVDEC path.

The six-hour source was not analysed in full during this verification. A separate 87,000-sample synthetic scene-detector run completed in 3,015 ms at 44.5 MB peak working set. It reuses source thumbnail patterns to isolate the detector's extra memory. This is not the total memory consumption of a six-hour real analysis. The removed HSV allocation alone would previously occupy roughly 4.8 GB at this sampling density.

The real video is the available MR Robot HEVC source; the 15-minute interval starts at 18:00. The two-minute interval used for the multi-source check starts at 20:00 and contains Tyrell, despite the source file's Elliot label. Three valid sources were tested: that interval, its byte-identical copy, and a two-minute Soldier Boy interval. Face evidence admitted the two Tyrell sources and rejected Soldier Boy (3 supplied, 2 selected). This exercises same-character source admission and copy suppression, not coverage across unseen seasons or labelled scene packs.

Additional regression coverage includes B-frame/reversed-order view targets, a long-GOP fixture, exact binary-cache round trips, corrupted/truncated cache rejection, cancellation during scene detection/identity clustering/camera checks, existing identity-conflict and copied-footage fixtures, both UI languages, Russian native-window rendering, lazy A/B decoder initialization and real bounded A/B playback. Animation tests wait for actual window exposure before measuring their completion, rather than timing an unexposed renderer.

Use `tools/benchmark/scene_memory_probe.cpp`, `dominant_probe.cpp`, `view_probe.cpp`, `run_matcher_scaling.py` and `run_analysis_smoke.ps1` to repeat the isolated and pipeline measurements. `pf_view_probe` supports independent `serial`, adaptive `batched` and bounded `parallel` modes; optionally pass a text file of `target start end` rows as its fifth argument. Keep video bytes, settings, model files, provider and cache conditions identical between builds. The update signing and actual archive-install verification remain part of `tools/release/build-windows.ps1`.

# Аудит модели и загрузки

## Что было сломано

1. UI показывал имена `yolo8*`, тогда как upstream и release-пакет используют
   `yolov8*`. Из-за этого выбор мог вести на несуществующий asset.
2. Выбор модели проверял только две папки и не видел `PF_MODEL_ROOT`/старый
   `D:\PF_CUDA\models` во всех сценариях.
3. Загрузка шла без прогресса и без manifest: нельзя было понять, что уже
   установлено, а повреждённый asset мог выглядеть готовым.
4. `.pt` из локального каталога ошибочно воспринимался как потенциальный
   runtime-файл, хотя PoseEstimator требует ONNX с batch-1.
5. Batch-8/16 не имели согласованного профиля и не должны были предлагаться
   как обычные модели.

## Что исправлено

* Добавлен единый каталог из canonical `yolov8`, `yolo11`, `yolo26` batch-1
  имён. UI показывает установленные модели с `✓`, отсутствующие с `↓`.
* Добавлен `manifest.json` через HTTPS с поддержкой массива `models` или
  объекта `models`; принимаются поля `url`/`downloadUrl` и `size`/`sizeBytes`.
* При выборе отсутствующего файла приложение получает manifest последнего
  release, скачивает в `.part`, показывает байтовый прогресс, проверяет размер
  и SHA-256, затем атомарно переименовывает файл в
  `%LocalAppData%\ParallelFinder\models`.
* При отсутствии manifest остаётся только HTTPS fallback по имени файла. UI
  явно сообщает, что такой файл скачан без проверки manifest; production
  release должен всегда содержать manifest.
* Смена модели блокируется на время загрузки, чтобы не было гонки между
  несколькими worker-потоками и settings.json.
* `PF_MODEL_PATH`, `PF_MODEL_ROOT`, папка рядом с exe, пользовательская папка
  и `D:\PF_CUDA\models` имеют единый порядок поиска.
* Добавлен `tools/model_export/export_pose_release.py`: он экспортирует ваши
  `.pt`, нормализует `yolo8` → `yolov8`, считает SHA-256 и пишет готовый
  manifest.

## Что остаётся проверить на машине с release

В текущем окружении нет опубликованного набора ONNX assets и нет OSNet/FastReID
модели, поэтому реальный сетевой download и body-ReID inference не запускались.
После публикации release проверить нужно:

1. Выбрать отсутствующий asset и дождаться 100%.
2. Повторно выбрать его — должен появиться `✓ установлена` без сети.
3. Повредить файл или изменить SHA в manifest — запуск должен отказать с
   ошибкой проверки, не подменяя рабочий файл.
4. Выбрать `dml`/`cuda`/`tensorrt` и убедиться, что preflight либо подтверждает
   backend, либо показывает причину недоступности; автоматического молчаливого
   fallback нет.
5. Запустить одинаковое видео после смены модели — кэш не должен переиспользовать
   признаки от предыдущей модели.

# RC19 validation

Recorded RC19 source, real-footage and regression checks. Signed packaging is gated separately by the release script; its verification logs accompany the local artifacts.

## Scope and measurement conditions

Actual inputs: Soldier Boy, 16,190 frames / 269.886 seconds, H.264 1920×1080; Elliot, 521,399 frames / 21,746.683 seconds, HEVC 3840×2160 10-bit. Hardware: Core Ultra 7 270K Plus, 24 logical processors, 64 GiB RAM, RTX 5070 12 GiB. CUDA recognition uses the same YOLO26m pose, OSNet body ReID, YuNet and SFace weights in both runs. The fast combined profile samples poses at 6 FPS and scene thumbnails at 4 FPS. Decoding traverses the complete input; a 521,399-frame input does not mean 521,399 pose-model calls.

Local resource reports include source paths and remain in ignored `build/rc19-audit`. The Python runner records process working set, private bytes, CPU time and remaining disk space every two seconds. Runs with window dumps also include the cost and memory of diagnostic JSON serialization. These are individual measured runs, not a universal speed guarantee.

The first complete Elliot run finished in 9,400,579 ms (2 h 36 min 40.579 s), with 194 pairs, 3,928 scenes and 23,867 windows. Its matcher stage took 6,582,233 ms: five main passes and five recovery passes repeated immutable retrieval/comparison work after face verification. Its peak working set was 7,043,624,960 bytes and peak private bytes 8,867,573,760 bytes. This first run already uses the new 10-bit NVIDIA decoder; it is the baseline for subsequent matcher changes, not a full RC18.8 CPU-decoding baseline.

The subsequent complete cold Elliot run finished in **5,220,548 ms (1 h 27 min 0.548 s)**, with 196 pairs, the same 3,928 scenes and 23,867 windows. Matcher time fell to **1,558,177 ms (25 min 58.177 s), a measured 4.224× stage speedup**; total application time improved 1.801×. The first main pass still compared 19,109,990 candidates and accepted 1,073,584 raw comparisons. Later face-verification passes reused those calculations; camera, identity veto and final selection still ran. Peak working set was 6,735,794,176 bytes and peak private bytes 8,428,978,176 bytes. Recognition/decode time was 3,087,388 ms under concurrent GPU workloads, slower than the first run: no controlled whole-pipeline recognition speedup is claimed. Preview generation took 231,769 ms for 392 images and still uses CPU decoding.

That cold binary precedes the final cropped-motion identity guard and early scratch-data release. The final binary completed a complete matcher replay on all original source observations with the same expanded policy: **1,820,158 ms application time (30 min 20.158 s), 187 pairs**, matcher **1,790,747 ms**, peak working set **4,888,084,480 bytes**, private bytes **5,738,049,536 bytes**, 911 resource samples. This replay does not repeat decoding or model inference and is not a cold-analysis timing. It retained 165 pairs from the preceding 194-result cropped-motion candidate, selected 22 different intervals and removed 29. All five newly frozen returning-camera body regressions were absent; both distinct-setting controls remained, and the known Slater/Elliot false pair remained absent. The already-known returning-table interval that lacks the strict decoded-pixel camera proof remains a limitation; the pixel threshold was not relaxed arbitrarily.

Two unrelated `video-transcriber` processes started during the candidate's recognition stage and registered GPU contexts. They were left running. Short GPU validation/analysis checks also overlapped part of this long run. This background load matters to total wall time; recognition-stage timing is not a controlled isolated comparison. Matcher-only serial/parallel and reuse checks report their own scope separately.

## Identity, duplicates and coverage

Five simultaneous real-footage excerpts were tested: three different Elliot packs, a byte-identical copy of one of them, and Soldier Boy as a foreign-person control. Shared identity admitted all four Elliot sources and rejected Soldier Boy. The single results list returned a distinct-setting body pair and a head-pose pair; the duplicate pack contributed no extra copy of either result. This checks admission, cross-source comparison and copy suppression on those excerpts. It does not establish recall across complete seasons, and an admitted source need not appear in the final disjoint-pair selection.

Original frames were decoded with FFmpeg and their PTS checked. Recorded keypoints were overlaid where a foreground person could be confused with the selected track. This found two repetitive cup/table body poses from a returning camera and one cropped motion of Christian Slater paired with Elliot. An additional 246 original frames from all 41 newly selected intervals in the cold candidate were reviewed. Five more returning table, computer, cup, aiming and office cameras showed why a 98.5% pose-score condition was insufficient: head/expression changes lower the geometry score without making the camera/body pose exclusive. Individual held-body pairs now require novelty against three measured decoded camera layouts, independent of that score. Real motions keep their lane and different-setting controls remain admitted.

The final replay's 22 newly selected intervals were also checked against 132 original FFmpeg-decoded frames. Recorded keypoints were overlaid on 12 ambiguous frames. This confirmed the selected background Elliot in a group scene, but also exposed an actor transition at the end of another interval and a photographed face being treated as a person. These are remaining tracker/liveness limitations, not validated exclusive parallels.

New regression fixtures preserve the actual observations and identity notes, with source paths redacted. They check false-positive suppression and retention of selected distinct-setting controls; they are prediction-derived regressions, not independent recall ground truth. Returning-camera proofs are computed once per shot pair using at most eight workers and one shared immutable statistics cache. Selection remains deterministic; progress is emitted only on the caller thread and cancelled jobs publish no partial result. A synthetic replication of the recorded controls checks serial/parallel equivalence separately from real-footage recall.

The independently frozen five Soldier body positives still have **0/5 strict representative-start recall**. Missing face admission, hidden wrists/legs, viewpoint and temporal-support requirements remain material limitations. The new six-result count must not be described as recovery of those five positives. The six-hour input has no exhaustive independent label set; losses of only a few percent are **not established**. Identity gates were not relaxed to inflate counts, and unshipped ROI refinement experiments are excluded.

## Bounds and regression coverage

Search-local main reuse has a 256 MiB maximum and a recovery child at half that budget, at most 384 MiB combined. The desktop further caps the main budget to available physical RAM / 64. Cached raw comparisons have no classification labels; geometry, appearance, source provenance and every search parameter are fingerprinted or compared exactly. Changing measured face observations reruns selection and the interval identity veto. Geometry or parameter changes invalidate cached calculations. The session owns and releases both caches; it must not be shared concurrently.

Quadratic alignment rejects windows over 512 frames. Identity pair veto storage is bounded to 32 MiB. Truncated, oversized-declaration and trailing-byte generic caches are rejected before payload allocation. Scene-sequence record counts are checked before reserving memory. Retrieval progress and cancellation run on the calling thread; worker cancellation is atomic and no partial cancelled result is published.

Once the exact comparison work list is built, the candidate hash table is released before worker result allocation. The work list is released after all workers join and before reuse/selection allocations. This removes overlapping ownership of millions of already-consumed records without deleting candidates; counters retain their original values and the final comparison progress callback runs on the calling thread. All 101 matcher tests pass with this lifetime change and the final returning-camera proof.

The diagnostic CLI can explicitly reuse source observations while retaining the expanded candidate policy (`run_long_analysis.py --warm --warm-expanded --cache ...`). Its cache override is ignored outside `--pf-analysis-smoke`; ordinary repeat analysis still invalidates the selected video caches. On Soldier, this replay completed in 1,181 ms of application time, with zero decoding/recognition samples, all six result records exactly equal apart from preview file paths, and cached previews. Its duration is too short for the runner's two-second memory polling; no peak-memory claim is made for that replay.

All 101 matcher tests pass after the cropped-motion and expanded returning-body-camera fixes. Three explicit NVIDIA tests pass: generated 10-bit frames, seeks in the actual six-hour source, and reversed targets through two parallel NVIDIA readers. CPU and NVIDIA RGB descriptors and native PTS are exact on those tests. Unvalidated pixel formats and geometry retain CPU fallback. Native Russian Qt UI checks pass with 38 tests and one opt-in network integration skip. Their reveal test now waits for native-window exposure and the actual final animation frame instead of checking an easing curve at a fixed timer deadline. The final CTest rerun passed all six targets in 74.71 seconds: core, updater, UI, application smoke, startup and matcher regressions. Signed portable extraction, application health/rollback and isolated native packaged startup are mandatory gates in `tools/release/build-windows.ps1`; a failed gate refuses packaging. Packaging does not substitute for independent recall validation.

## Cleanup and remaining limits

Only generated diagnostics and superseded build directories were moved to a reversible local archive. Three complete observation dumps were compressed and byte-for-byte SHA-256 checked against their retained originals; test inputs, model weights, signing keys and existing release artifacts were preserved. Release archives contain only tracked current source files and explicit runtime files. Local videos, logs, caches, profilers and user CMake presets are ignored.

No unbounded memory growth was observed during these finite full-input runs. Allocation bounds and cancellation regressions are covered; this is not proof of absence of every leak, vulnerability or long-session UI issue. Remaining independently verified misses are documented above. Some same-camera portraits, repeated movements and photographed faces are not exhaustively classified; the result count is not a precision or recall metric.

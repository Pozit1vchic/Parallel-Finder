# Предрелизный аудит — 2026-09-20

> История подготовки RC. Текущее состояние, опубликованные каталоги и оставшиеся задачи — в [AUDIT.md](../AUDIT.md). Старые отметки о процентах, качестве, отмене экспорта и недоступных assets ниже не описывают текущую ревизию.

## RC.11 — 2026-09-30

- Видимый жест конечностей не сопоставляется с головой/плечами другого отрезка, в котором эти конечности скрыты. Исправлена пользовательская Dean-пара «скрещённые руки / пистолет».
- Добавлены непрерывные уверенные участки статичной позы без повторного inference: минимум три наблюдения за 0,30 секунды. Проверка того же персонажа остаётся обязательной.
- Dean: 7 → 8 кандидатов; дополнительное прицеливание около 2,7 / 6,3 с найдено, три пользовательские контрольные пары сохранены. Soldier: три контрольные пары также сохранены; не все неразмеченные карточки объявляются правильными.
- Полный CTest 5/5 и запуск из упакованной папки проверены; упакованный CUDA-прогон Dean повторил результат и не принял четыре отмеченных отрицательных.
- [Методика и ограничения проверки](matcher-supported-poses-2026-09-30.md). Проценты остаются оценками алгоритма, не вероятностью истинности пары.

## RC.10 — 2026-09-30

- Проверка GPU начинается в фоне после первого кадра окна; QML читает готовый снимок состояния и не ждёт mutex проверки. До готовности нельзя запустить анализ или установку провайдера.
- Неиспользуемые MediaPlayer/VideoOutput A/B не создаются в пустом окне; при удалении результата освобождаются. Встроенное одиночное и совместное воспроизведение сохранено.
- PNG-превью сохраняются с меньшими затратами CPU без потерь от сжатия; убрана повторная копия буфера перед pose inference. Анализ, модель и пороги не упрощены.
- Отбор кандидатов поз не тратит ограниченную очередь на людей, которые уже не проходят обязательную проверку личности. Новый тест воспроизводил пропуск до исправления и проходит после него, включая обратный порядок входных данных.
- [Замеры, контрольные пары и ограничения проверки](startup-preview-matcher-2026-09-30.md).

## RC.9 — 2026-09-30

- Многопоточное CPU-декодирование ограничено восемью потоками; для больших NVIDIA-источников добавлен NVDEC с безопасным CPU-fallback.
- В память CPU скачиваются только кадры для анализа. Рабочее разрешение по-прежнему не больше 1280×720; оригинал и таймкоды сохраняются.
- Экспериментальный GPU-resize не включён в интерфейсе: на контрольном видео он ухудшил отбор пар. В рабочей версии сохранён прежний способ уменьшения.
- Источники не больше 1080p, повёрнутые/анаморфные/чересстрочные и непроверенные цветовые форматы остаются на CPU. Кэш разделяет реально выбранные декодеры.
- [Методика измерения и границы проверки](video-decode-performance-2026-09-30.md). Это ускорение чтения, не гарантия ускорения всей обработки в несколько раз.

## RC.8 — 2026-09-30

- Точная нарезка перематывает к нужному месту до декодирования; программный fallback быстрее и ограничен по потокам.
- Текущий клип показывает процент; отмена завершает FFmpeg, при двух минутах без продвижения срабатывает watchdog.
- Успешный кодировщик повторно используется для следующего клипа. Готовые файлы не удаляются при отмене или неудачной замене.
- Поиск кандидатов адаптивно обходит соседние наблюдения той же сцены, сохраняя прежние проверки персонажа и сходства.
- Контрольные пары Dean/Soldier и ограничения этой проверки описаны в актуальном аудите; это RC, а не гарантия поиска всех параллелей.

## RC.3 — 2026-09-21

- Статус в шапке переводится при переключении языка; раскрытие дополнительных настроек не разрывает привязку состояния. Добавлены UI-регрессии первого клика и RU/EN.
- Настройки оформления перенесены из реестра в общий атомарный settings.json вместе с настройками анализа. English при отсутствии файла; прежние записи оформления в реестре не удаляются и больше не используются.
- DirectML загружается из двух официальных Microsoft NuGet пакетов с фиксированными SHA-256. Устанавливаются только Windows x64 release DLL и лицензии. CUDA/TensorRT release assets всё ещё отсутствуют.
- Загруженные runtime хранятся в AppData; пользователь может положить собственный полный комплект в providers/{cuda,tensorrt,dml} рядом с EXE и выбрать его до перезапуска. Убрано автоматическое использование D:\PF_CUDA\onnxruntime.dll.
- Установщик всегда показывает выбор папки; правила gitignore исключают локальные runtime, маркеры активации, временные загрузки и дампы.
- Дополнительная инструкция: docs/GPU-SETUP.md. Проверка на чистой Windows и NVIDIA CUDA/TensorRT остаётся обязательной перед стабильным выпуском.

Сборка 0.1.0-rc.1 предназначена для проверки. Это **не разрешение на стабильный публичный релиз**.

## Проверено до упаковки

- Сборка с предупреждениями компилятора; четыре набора CTest.
- Исправлено визуальное состояние выбора «Точно/Быстро» и нумерации; QtTest нажимает реальные кнопки и проверяет состояния.
- Убраны некалиброванные проценты из списка и панели сравнения. Внутренний score остаётся для сортировки и экспорта, не является вероятностью.
- Сравнение пяти точек головы подписывается отдельно от позы тела.
- MP4-экспорт перенесён с GUI-потока в worker; повторный запуск запрещён до завершения. Порядок «Как в видео» применяется и для MP4.
- Адреса моделей и runtime закреплены за отдельными тегами: v0.1.0-models и runtime-v1. Выпуск приложения больше не меняет назначение releases/latest для загрузчика.
- Большие веса, сборки, локальные логи и .env исключены из Git. Исходники тестов включены.

## Стоп-факторы публичного стабильного релиза

1. Контроль качества остаётся 2/3 положительных параллелей; эвристики масок/сцен не проверены на представительной выборке.
2. Дистрибутив использует GPL-сборку FFmpeg и другие зависимости MSYS2. Нужны точная ведомость лицензий и выполнение обязательств предоставления соответствующих исходников; простое копирование LICENSE и ссылка на upstream не завершают эту проверку.
3. Происхождение и условия распространения конкретного body-ReID ONNX должны быть закреплены рядом с весами.
4. NVIDIA-пакеты не включены: совместимость с AGPL и условия распространения конкретных CUDA/cuDNN/TensorRT компонентов не подтверждены.
5. Требуются чистая Windows VM, DPI/длительные сессии, реальные GPU и тест установки/удаления без среды разработчика.
6. Полный RAII-рефакторинг ONNX и проверка закрытия приложения во время worker-задач не завершены. MP4-экспорт пока без отмены.

Старые выводы AUDIT.md о синхронном MP4-экспорте исправлены этим этапом. Числа предыдущего видео-прогона не являются измерением новой сборки.

## Дополнение: проверка упаковки

### Исправление запуска RC.2

В RC.1 обычный запуск обеих пользовательских копий завершался кодом 1: Qt не находил модули QtQuick в поставляемой папке qml. Предыдущий --pf-smoke не загружал интерфейс и пропустил этот дефект. Добавлены переносимый qt.conf и явный app-local путь QML в приложении. Добавлен --pf-ui-smoke: он загружает настоящий Main.qml и завершается успешно только после frameSwapped; отсутствие окна или таймаут считаются ошибкой. Упаковка теперь запускает эту проверку с очищенными путями Qt/QML и PATH без инструментов разработчика до создания архивов. На пользовательских установленной и portable-копиях добавление qt.conf восстановило обычное открытие окна. Проверка на чистой Windows VM всё ещё требуется.

Предыдущая RC прошла запуск с PATH без MSYS2 и короткий анализ 8-кадрового тестового видео (CPU, локальные упакованные модели). Это проверка комплектности DLL, не замена чистой Windows VM и не оценка качества матчера. Новая RC также включает перенос галочки масок в левую панель, русскую/английскую подсказку, обложку README и исходники проекта отдельным ZIP. NVIDIA runtime assets и окончательная юридическая проверка по-прежнему не готовы.

## Упаковка

tools/release/build-windows.ps1 повторно запускает сборку и CTest до создания архивов. Создаёт новую staging-папку без удаления существующих файлов, собирает Qt/native DLL, базовую модель и вспомогательные модели, генерирует SHA-256 ведомость, ZIP и per-user Inno Setup installer. CUDA/TensorRT не устанавливаются. Установщик не требует администратора и не меняет системный PATH.

Portable здесь означает «без установщика», не полную изоляцию пользовательских настроек от AppData.

# RC.13 — интерфейс, полный кэш и объединённый экспорт

Проверки от 30 сентября 2026. Исходные видео, веса, provider DLL, настройки пользователя и обложка README не изменялись.

## Что изменено

1. В матчерe одно временное выравнивание используется и для проверки непрерывности жеста, и для оценки; зеркальная проверка читает подготовленные данные по ссылке, без копирования всего окна. Частота наблюдений и пороги не снижались.
2. Версия кэша 8 сохраняет контекст и число сцен вместе с позами и identity-признаками. Старый кэш версии 7 требует одного прохода для обновления. Полный повторный проход не декодирует исходник для анализа и не запускает inference; итоговые кадры превью читаются отдельно. Пустая гистограмма тёмного кадра допустима.
3. Источники находятся внутри drag&drop, над кнопками добавления и удаления. Неактивные действия не подсвечиваются акцентом.
4. Навигация результатов останавливается на концах; плавающая «↑ Вверх» возвращает к первой карточке. Сортировка — один список из шести вариантов.
5. «Совместить все клипы по возрастанию таймкодов» собирает один MP4 в фоне, с прогрессом и отменой. Точные дубликаты диапазонов удаляются; частичное перекрытие не склеивается. При равных таймкодах используется имя исходного файла.
6. Для объединения разные клипы приводятся к размеру/FPS первого, с сохранением пропорций и stereo/48 kHz; для немых клипов добавляется тишина. Это требует перекодировки, поэтому «Быстро» недоступно. Итог заменяется атомарно только после успеха; staging удаляется при успехе, ошибке и отмене. Аварийное завершение ОС во время экспорта может оставить скрытую staging-папку в выбранной пользователем папке экспорта.
7. Режим «Костюм / маска», специальная ветка сравнения, свойство QML, поле настроек и диагностический переключатель удалены. Старое поле JSON игнорируется. Обычная проверка лица и тела не отключается.
8. Превью принадлежат отдельному временному сеансу. При нормальном выходе он удаляется; при следующем анализе собственные аварийные сеансы старше суток очищаются. Активный экземпляр защищён lock-файлом. Неизвестные файлы и ссылки не удаляются.

## Измерения и ограничения

### Доработка оформления

Компоновка, палитра, пользовательский акцент, обложка и SVG сохранены. В пустом сравнении и заголовках использован связанный мотив A/B; кадр проявляется после фактической загрузки изображения, при переключении пары коротко выделяются обе рамки. Видео не масштабируется и не копируется ради перехода. Появление ограничено первыми шестью карточками результатов, а не тысячами элементов; остальная выдача остаётся виртуализированной. Раскрытие настроек, стрелки списков, галочки и прогресс имеют короткие переходы 120–220 мс. Постоянное мигание GPU удалено.

Переключатель «Отключить анимации интерфейса» проверен тестом: смена пары без перехода, остановка начатого перехода, немедленное завершение раскрытия и отсутствие зависшей полупрозрачной рамки. Это ограниченный набор лёгких эффектов; измерений FPS/энергопотребления на слабых GPU ещё нет.

Moshenniki: 27:19, 1920×960, 25 FPS, 40 976 кадров; CUDA, YOLO26m, быстрый профиль, гибрид.

| Проход | Время | Результат |
|---|---:|---|
| RC.12, позы в кэше, повторное декодирование | 41,377 с | 44 пары |
| RC.13, обновление кэша 7 → 8 | 31,921 с | те же 44 пары |
| RC.13, полный кэш 8 | 6,522 с | те же 44 пары |

В финальном проходе matcher — 2,305 с, создание 56 уникальных превью — 4,176 с. Таймкоды, типы, similarity, sceneSimilarity, rankScore, face/identity flags сравнивались с RC.12 и совпали. Статистика кадров сохраняется; отсутствие декодирования не означает нулевую длину видео.

Это ускорение повторного анализа, не первого знакомства с материалом. Первый проход всё ещё платит за декодирование, перевод изображения и inference; общая точность 44 карточек не размечена. Чисто вычислительное ускорение матчера не заявляется по одному замеру: у большинства карточек этого материала статичный тип, где временное выравнивание не применяется.

Dean: 8 кандидатов, 4/4 положительных anchors, 0/4 отрицательных приняты. Soldier: 52 кандидата, 3/3 положительных, 0/5 отрицательных приняты. Специальный режим маски больше не тестируется как функция приложения. Из маленьких контрольных наборов нельзя выводить общую полноту/точность.

## Воспроизведение

- `tools/benchmark/run_analysis_smoke.ps1`: одинаковые видео, модель, runtime, качество и режим; первый проход обновляет старый кэш, второй измеряет полный кэш. Диагностика `PF_DEBUG_ANALYSIS=1` показывает `complete_cache_hit=1 decoded=0`.
- `tools/benchmark/check_reference_pairs.ps1`: `dean-reference.json` и `soldier-reference.json` проверяют положительные и отрицательные anchors.
- `MontageExport.*`: реальный FFmpeg, разные разрешения/FPS, звук и тишина, порядок красного/синего кадров, исключение дубликатов, отмена после первого клипа, сохранение старого результата и очистка staging.
- `RuntimeScratch.*`: чужие файлы сохраняются, старые собственные удаляются, действующий второй сеанс не затрагивается, нормальный выход убирает собственную папку.
- UI-тесты проверяют расположение источников, края навигации, стрелки после фокуса другой кнопки, шесть сортировок и включение объединённого экспорта.

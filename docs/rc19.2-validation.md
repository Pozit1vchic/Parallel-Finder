# RC19.2 analysis and matcher performance validation

## Scope

RC19.2 changes scheduling and exact preprocessing, not recognition weights, sampling frequency, candidate budgets, identity gates, motion thresholds, duplicate checks or selection policy. Hardware: Core Ultra 7 270K Plus (24 logical processors), 64 GiB RAM, RTX 5070 (12 GiB). The previous RC19.1 executable was retained for direct comparisons. Individual runs use the same input, YOLO26m pose, face/ReID models and CUDA provider. Other user applications are left running; no two heavy benchmark analyses are intentionally run together in the final controlled comparisons.

## Implementation and bounds

An ordered worker runs pose inference while the caller handles face/ReID/tracking for earlier samples. Owned frame buffers prevent decoder reuse from invalidating queued pixels. Outstanding batches include pending input, active inference and ready results. The queue holds at most three batches and shares the existing 128 MiB raw pose staging budget with producer and consumer batches. Excessively large fixed batches use the sequential path. CPU inference and an explicit one-thread setting also retain the sequential path. Normal analysis keeps the shipped batch-one model.

The three face preprocessing paths reuse RGB bilinear coordinates and pixel addresses. Arithmetic order within each channel is unchanged; 10,000 randomized coordinates and border, out-of-bounds and nonfinite cases compare bitwise with the prior scalar calculation.

Candidate filtering uses dynamically claimed blocks of 2,048 keys. Exact comparisons use blocks of 1,024 tasks. Both phases merge blocks in original task order before selection. Missing identity facts are memoized in bounded worker-local maps; immutable existing facts are shared. Candidate hash nodes are released before filtering, and key/block storage is released before exact comparisons. Progress counter updates are batched in groups of 64. Automatic workers follow hardware concurrency, capped at 256 and bounded by useful work. This does not promise every stage keeps every core or GPU execution unit occupied.

Internal rejected/mirrored/torso comparison alternatives do not copy long source-path strings. Source IDs are materialized once for each surviving hypothesis before deterministic selection; public standalone comparisons retain their original complete result fields, including rejected results. All scores, intervals and provenance still derive from the same source windows.

Appearance/face ANN retrieval also runs in parallel, in waves of at most 512 query windows. Per-window neighbor order and original candidate insertion order are preserved. ANN query memo payloads share the preceding 16 MiB total budget across workers; workspace count and missing identity-fact budgets are divided across workers rather than multiplied by thread count. Shared identity facts are read-only while workers run and are merged only after joining a wave. A separate identity-retrieval stage reports progress and cancellation on the caller thread. Serial/parallel field-equivalence regression inputs cross the wave boundary.

Preview decoding follows the validated NVIDIA policy for sources larger than Full HD when a NVIDIA provider is selected. It preserves the previous 1920x1080 working size and CPU resize, supports the explicit CPU override, and retains decoder fallback for unavailable devices, unvalidated formats or unsupported geometry. A real six-hour 10-bit input test compares CPU/NVIDIA Full HD preview bytes and PTS at six reversed seeks across the whole source.

Cancellation callbacks and progress remain on the calling search thread; workers read a shared atomic cancellation flag. Cancellation joins in-flight workers and returns no partial result. Inference queue errors propagate to the caller and its worker joins before referenced model/transform state is destroyed.

Cancelled inference submissions return false without moving the caller's owned input, both before and after worker shutdown. A cancellation arriving as the worker publishes its stopped state cannot turn ordinary user cancellation into a closed-pipeline exception. A gated worker regression checks both sides of this race. The pipeline cancellation predicate may run on its caller and worker and reads the controller's shared atomic cancellation flag.

Camera-thumbnail comparison retains the original shifted grid, channel order, weights and threshold. The original full weight is exactly 702 for the unshifted grid and 648 for either one-column shift. After each row, an accumulated nonnegative prefix is divided by this original full denominator. If it already exceeds the threshold, remaining rows cannot restore a passing result. Division is retained rather than multiplying the threshold, avoiding a changed rounding boundary. Every pixel is validated before early rejection. A frozen full-work reference agrees on 20,000 randomized shifted inputs in both orientations, plus threshold-neighbor and late-invalid-pixel cases.

## Completed short-input comparison

Soldier Boy: 16,190 source frames, 269.886 seconds, 1920x1080 H.264. Both final comparison runs start from an empty, separate cache.

| --- | ---: | ---: |
| Application analysis time | 33,801 ms | 25,374 ms |
| Runner wall time | 35.114 s | 26.846 s |
| Sampled peak working set | 1,617,272,832 bytes | 1,626,079,232 bytes |
| Sampled peak private bytes | 3,008,106,496 bytes | 3,031,818,240 bytes |
| Returned pairs | 6 | 6 |

Application time is 24.93% lower (1.332x faster). Every result field and ordering matches, except temporary preview URLs. Entire dumped observation JSON files are equal. Sampling, identities and timestamps are preserved, not just the pair count. RC19.2 reports 1,619 pose samples, 211 tracks and a peak of three outstanding pose batches. Resource polling is every two seconds; sampled peaks do not prove absence of leaks. The frozen validated executable SHA-256 is `313ed52e0e60c9b2c972dc8bc9a6a57f1ea25a14c894b4b6033d5e0dac2e64b2`.

The final five-source replay preserves both preceding results and every field/order. It contains three Elliot excerpts, a copied pack and Soldier as a foreign-person control; identity admission and copy suppression remain equal. A separate eight-second Soldier excerpt completes using the CPU provider, CPU decoding and the sequential pose path, with no overlap pipeline. This is a fallback smoke check, not a CPU performance comparison or full-season recall test.

The full-source matcher replay reuses the existing complete observation cache, including expanded retrieval. This measures matching and result preparation, not video recognition. Both versions operate on the same 521,399-frame, 21,746.683-second, 3840x2160 10-bit HEVC source.

Matcher time is 5.74% lower; application total is 5.87% lower. Every final pair field and order matches, except temporary preview URLs. The runner wall time is 676.203 seconds. Primary appearance/face retrieval takes 20.717 seconds; primary exact comparison/filtering takes 221.329 seconds. Primary selection, including nested recovery work, remains the dominant cost at 399.202 seconds. A sampled parallel comparison interval uses about 19 of 24 logical CPU processors; serial selection does not continuously occupy all processors. This change does not move the motion matcher onto the GPU.

The final empty-cache run completes on the same frozen executable and all four unchanged recognition models. Every final pair field and order is exactly equal to both the RC19.1 reference and the RC19.2 replay, except temporary preview URLs. The source and preview decoders report `nvdec` with no fallback. Pose overlap reports a peak of three outstanding batches, and decoder prefetch also stays at three frames. The source pipeline reuses 41,005 scene samples. During scene refinement, separate whole-device checks measure the NVIDIA video decoder at 99–100% while GPU compute is approximately 11%; these are distinct engines. Whole-device telemetry includes other applications. Pose, face and ReID timers overlap and must not be added as separate sequential durations.

This is a completed end-to-end validation, not a controlled RC19.1-versus-RC19.2 cold performance comparison. The controlled version comparisons are the fresh Soldier runs and the full-input matcher replay above. Iterative matched-face verification and changing recovery worklists remain a substantial cost of a first full analysis. The final complete run deliberately performs the existing verification policy rather than truncating its rounds or reducing retrieval budgets.

## Test gates and rejected experiments

All six configured CTest targets pass: core/GPU tests, update tests, UI tests, application smoke, startup isolation and matcher regression. The core/GPU executable runs 322 tests: 304 pass and 18 optional environment-dependent tests skip in the normal gate. The matcher regression target separately passes 47 tests. The opt-in Full HD NVIDIA preview test also passes separately on the actual six-hour 10-bit input, comparing bytes and PTS at six reversed seeks. Added tests cover ordered move-only frame ownership, capacity/backpressure, inference failure, cancellation and repeated shutdown; face sampling equivalence; camera-prefix equivalence; and cancellation during parallel candidate preparation and identity retrieval. Serial/parallel matcher tests compare result fields and ordering on worklists large enough to cross block and wave boundaries. GPU occupancy telemetry, when enabled, covers the whole device and includes other applications.

A static batch-eight ONNX export from the original pose checkpoint retains all 242 initializer arrays exactly and passes ONNX validation, but changes numerical observations/tracks and did not demonstrate a reliable end-to-end gain. It is not selected or included in the release. A larger exact full-window camera cache preserved the 187 results but made the tested full matcher slower; it was removed. The shipped RC19.1 representative camera memo remains intact.

## Limits

Preserving existing results does not establish exhaustive recall or absence of false positives. The independent five-example Soldier body-parallel deficit described in RC19 validation remains unresolved; this performance release does not claim to fix it. These measurements apply to the tested hardware, providers and inputs. A currently running older executable must finish or be cancelled normally before using a new executable. The packaged native startup, all six CTest targets, signed archive installation/health check, pinned Ed25519 signature and per-file integrity checks are mandatory packaging gates.

## Коротко

В GitHub нужны **ZIP-пакеты и один `providers.json` в Release с тегом `runtime-v1`**, не отдельные DLL в исходниках. Приложение уже читает этот адрес:

`https://github.com/Pozit1vchic/Parallel-Finder/releases/download/runtime-v1/providers.json`

Ничего в `System32`, системный PATH или папку установки программы копировать не нужно. Кнопка устанавливает пакет в `%LOCALAPPDATA%\ParallelFinder\ParallelFinder\providers\cuda` либо `tensorrt` (`dml` для DirectML). До реализации отдельного процесса анализа после смены runtime нужен перезапуск приложения. Драйвер NVIDIA остаётся отдельной системной зависимостью.

## 1. Откуда брать файлы

В PowerShell из `D:\Parallel-Finder`:

```powershell
./tools/release/prepare-provider-packages.ps1
```

Скрипт создаёт **новую** папку `release/runtime-input-<id>` и выводит её путь. Уже установленные комплекты и исходные библиотеки он не меняет. Внутри:

```text
runtime-input-<id>/
  cuda/       — ORT CUDA + CUDA 12 + cuDNN 9, DLL рядом
    licenses/
  tensorrt/   — свой ORT + CUDA/cuDNN + TensorRT 10, DLL рядом
    licenses/
  dml/        — отдельный комплект ORT DirectML
    licenses/
  inventory.json
  HOW-TO.md
```

Основной источник — готовые папки приложения в AppData. Только отсутствующие cuDNN/TensorRT DLL берутся из конкретных каталогов `D:\CUDA_Libraries\cudnn-windows-x86_64-9.10.0.56_cuda12\bin` и `D:\CUDA_Libraries\TensorRT-10.9.0.34\lib`. Скрипт не копирует Toolkit целиком, примеры, Python-пакеты, модели или драйверы. Хэши и версии записываются в inventory.

Если собираешь вручную, переноси **все `onnxruntime*.dll` одного провайдера из одной сборки**. Не заменяй один ORT DLL из чужого комплекта. TensorRT-пакет содержит также CUDA-провайдер и его зависимости для fallback. Одного `nvinfer_10.dll` недостаточно: нужны остальные runtime-библиотеки, включая builder resource для построения engine. DirectML хранится отдельно от NVIDIA ORT.

## 2. Лицензии и проверка перед публикацией

В `cuda/licenses` и `tensorrt/licenses` нужны исходные документы соответствующих дистрибутивов: `ONNX-Runtime-LICENSE.txt`, `CUDA-EULA.txt`, `cuDNN-LICENSE.txt`; для TensorRT также `TensorRT-LICENSE.txt` и применимые third-party notices. Для DirectML — документы ONNX Runtime и DirectML. **Не создавай пустые файлы с этими именами и не подменяй их лицензией проекта.**

Подготовка копирует найденные локальные документы; список отсутствующих будет в `validation.json`. Наличие файлов лицензий само по себе не подтверждает право распространения: перед публичной публикацией нужно проверить условия именно этих версий и совместимость с лицензией приложения. Полная модель должна пройти inference на целевой NVIDIA и чистом окружении; текущий probe проверяет создание сессии, а не правильность и скорость работы всех моделей.

## 3. Создать ZIP и манифест

Подставь путь, который вывел первый скрипт:

```powershell
./tools/release/build-provider-packages.ps1 -InputRoot 'D:\Parallel-Finder\release\runtime-input-<id>'
```

Он проверит каждый комплект отдельным процессом, убрав CUDA Toolkit из PATH этого процесса, затем создаст новую `release/runtime-assets-<id>`:

- `parallel-finder-runtime-cuda-win64.zip`
- `parallel-finder-runtime-tensorrt-win64.zip` — локальная полная копия; если она больше лимита GitHub, рядом создаются `.zip.part001`, `.zip.part002` и т. д.
- `parallel-finder-runtime-dml-win64.zip`
- `providers.draft.json` — реальные размеры, SHA-256 и готовые URL.
- `validation.json` и журналы проверки — **не загружать как манифест**.

DLL лежат непосредственно в корне ZIP. После упаковки архивы не редактировать: изменение любого байта требует пересчёта хэша и размера. Скрипт не перезаписывает старые результаты, не публикует релизы и не меняет настройки установленного приложения. ZIP от 2 GiB автоматически разбивается на обычные байтовые части до 1800 MiB; новая версия приложения скачивает их по манифесту, проверяет каждую и полный собранный ZIP, затем распаковывает. Это не многотомный формат ZIP/7z. Требуется сборка приложения с поддержкой `parts` — старые installer/portable её не имеют. Общий архив ограничен 8 GiB.

## 4. Что именно закинуть на GitHub

После проверок из пункта 2:

1. Открой **Releases → новый или существующий Release с тегом `runtime-v1`** в `Pozit1vchic/Parallel-Finder`.
2. Загрузи CUDA/DML ZIP и **части TensorRT**, если в его записи есть `parts`: строго все файлы из `parts[].archive`, **без переименования**. Большой полный TensorRT ZIP в этом случае не загружай. Дождись окончания загрузки всех файлов.
3. Проверь `validation.json`, дополни недостающие документы и пересобери ZIP, если состав изменился.
4. Возьми `providers.draft.json`, назови копию **`providers.json`** и загрузи **последним**. Если в существующем манифесте есть другие комплекты, сохрани их записи, не удаляй молча.
5. Опубликуй Release; проверь доступность ссылок из JSON без авторизации. Draft/private release обычные пользователи скачать не смогут.
6. Используй обновлённую сборку с поддержкой `parts`; проверь кнопку скачивания на отдельном пользовательском профиле/чистой машине, затем перезапуск и анализ. Не удаляй собственные рабочие провайдеры ради теста.

Не коммить ZIP и DLL в Git. Не клади их в обычный релиз приложения вместо `runtime-v1`: текущая кнопка не ищет «последний релиз». При обновлении используй новые имена ZIP и сначала публикуй архивы, потом соответствующий манифест, чтобы старый JSON не ссылался на заменённый файл с другим хэшем.

## Проверенные ограничения

В найденных локальных комплектах: ORT FileVersion `1.24.20260316.3.2d92497` для CUDA/TensorRT; cuDNN 9.10.0.56; каталог TensorRT 10.9.0.34. Официальная таблица ORT не заменяет тест конкретной сборки: нельзя независимо обновлять каждый компонент до «самого нового».

На момент подготовки публичный API GitHub вернул 404 для `runtime-v1`: это означает, что доступный без авторизации релиз по этому адресу не подтверждён, а не доказательство отсутствия приватного/draft-релиза. Пока NVIDIA assets и манифест не доступны, кнопкам CUDA/TensorRT скачивать нечего; у DirectML есть отдельный путь скачивания из NuGet.
